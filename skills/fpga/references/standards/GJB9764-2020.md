## 3 术语和定义、缩略语

### 3.1 术语和定义

GB/T 11457 确立的以及下列术语和定义适用于本标准。

#### 3.1.1 可编程逻辑器件软件单元（programmable logic device software unit）

具有输入、输出接口的可编程逻辑器件软件模块。模块的表现形式可以为程序代码、原理图、波形文件等。

#### 3.1.2 可编程逻辑器件软件配置项（programmable logic device software configuration item）

可单独进行配置管理的一个或多个可编程逻辑器件软件单元集合。

#### 3.1.3 可编程逻辑器件软件系统（programmable logic device software system）

相互间具有连接关系的可编程逻辑器件软件配置项集合。

## 4 一般要求

### 4.1 文档种类

可编程逻辑器件软件开发过程中一般产生下列文档：

1. 接口需求规格说明（IRS）；
2. 接口设计说明（IDD）；
3. 可编程逻辑器件软件可行性和风险分析报告（PLDSFARAR）；
4. 可编程逻辑器件软件研制任务书（PLDSDTD）；
5. 软件开发计划（SDP）；
6. 软件配置管理计划（SCMP）；
7. 软件质量保证计划（SQAP）；
8. 软件移交计划（STrP）；
9. 可编程逻辑器件软件需求规格说明（PLDSRS）；
10. 可编程逻辑器件软件设计说明（PLDSDD）；
11. 可编程逻辑器件软件仿真测试计划（PLDSSTP）；
12. 可编程逻辑器件软件仿真测试说明（PLDSSTD）；
13. 可编程逻辑器件软件仿真测试报告（PLDSSTR）；
14. 可编程逻辑器件软件确认测试计划（PLDSVTP）；
15. 可编程逻辑器件软件确认测试说明（PLDSVTD）；
16. 可编程逻辑器件软件确认测试报告（PLDSVTR）；
17. 软件产品规格说明（SPS）；
18. 软件版本说明（SVD）；
19. 可编程逻辑器件软件使用说明（PLDSUD）；
20. 可编程逻辑器件软件研制总结报告（PLDSDSR）；
21. 软件配置管理报告（SCMR）；
22. 软件质量保证报告（SQAR）。

### 4.2 文档编制

文档内容根据 GJB 9432 各阶段工作任务产生，描述军用可编程逻辑器件软件开发过程中的主要活动信息和要求。开发方应按本标准记录有关信息、编写有关文档，并按合同或研制任务书要求交付。电子文档应规定格式，如 DOC、PDF 等。

文档可采用图、表、矩阵或其他表示形式，使章条信息清晰可读。正文目录采用小写罗马数字编号；正文和附录采用阿拉伯数字顺序编号。一个文档分卷时，每卷重新顺序编号。

标准正文中 `X`、`Y` 是小条编号自变量；标题圆括号中的文字在实际编写时应替换为真实内容。例如 PLDSRS 的 `3.2.X` 可展开为 `3.2.1 图像数据采集-R001`、`3.2.2 看门狗复位-R002`。

### 4.3 文档结构

#### 4.3.1 文档构成

文档一般由封面、修改页、目录、正文和附录组成。

#### 4.3.2 封面

封面宜包括：

- 文档标识及版本号；
- 密级；
- 编制/修订日期；
- 文档名称；
- 编制单位；
- 编写；
- 审核；
- 批准。

#### 4.3.3 修改页

修改页应包括修改时间、修改内容和修改人等。

#### 4.3.4 目录

目录一般包括章、条、图表、注释和附录的编号、标题及所在页码。

#### 4.3.5 正文

正文为各文档具体内容，详细要求见第 5 章。

#### 4.3.6 附录

附录应提供便于文档维护、可以单独发布的信息，如图、表、分类数据等。每个附录都应在正文中被引用；附录可以单独装订成册。

### 4.4 文档剪裁

承制方可根据 GJB 9432、所选生存周期、合同或研制任务书及实际活动确定文档种类，并可合并或拆分：

- 合并两个或多个文档时，应选定主文档，将其他文档内容有机组合到主文档；合并后的文档要素应保持完整，并在注释中说明。
- 拆分一个文档时，各拆分文档的结构均应符合 4.3，拆分前后文档要素应保持一致，并在其中一份文档的注释中说明拆分情况。
- 裁剪章条时，标题顺序仍应与本标准一致；被裁剪章条应在原位置标明“本章无内容”或“本节无内容”并说明理由。整章裁剪只需在最高层章条处说明。
- 需要时可编制《运行方案说明》《系统/子系统规格说明》《接口需求规格说明》《系统/子系统设计说明》《接口设计说明》，其要求见 GJB 438B-2009。

### 4.5 文档说明

测试文档按测试级别编制：

| 测试级别 | 一般编制的文档 |
|---|---|
| 单元测试 | PLDSSTP、PLDSSTD、PLDSSTR |
| 配置项测试 | PLDSSTP、PLDSSTD、PLDSSTR、PLDSVTP、PLDSVTD、PLDSVTR |
| 系统测试 | PLDSVTP、PLDSVTD、PLDSVTR |

GJB 9432 的验收与交付阶段产生用户手册文档；本标准的 PLDSUD 同时覆盖用户手册和器件固化内容。

## 5 详细要求

### 5.1 可编程逻辑器件软件可行性和风险分析报告（PLDSFARAR）

PLDSFARAR 描述可行性和风险分析，通常包括：设计资源评估、功耗评估、基于系统时序分析的工作频率评估、防辐照方法及其资源/频率影响、需求可测试性评估、芯片属性可行性、基线技术要素有效性、人力资源可用性、第三方 IP 核的许可/合法性/经济可行性、采用 PLD 的必要性、继承性设计可行性与风险，以及采购、工具、人员、需求变更、供货周期和备件等风险的预防措施和意外计划。正文格式见附录 A。

### 5.2 可编程逻辑器件软件研制任务书（PLDSDTD）

PLDSDTD 描述开发目的、目标、主要任务、功能和性能指标，是开发基础和依据。应包括：

- 运行环境要求，如温度、电压、功耗、抗辐照、芯片型号；
- 技术要求，包括系统分配的功能、性能和算法指标；
- 全部外部接口关系、建立/保持时间、功能处理时间、精度和接口时序指标；
- 可靠性、冗余、健壮性、安全关键等级、安全性及软件可编程等关键性要求；
- IP 核复用、资源余量、时序余量等设计约束；
- 开发进度、评审和控制节点等管理要求；
- 标准、文档、配置管理、测试和分承制方等质量保证要求；
- 验收准则、交付形式/数量/媒体、交付文档和必要的版权保护；
- 验收后的改正性、适应性和完善性维护原则。

正文格式见附录 B。

### 5.7 可编程逻辑器件软件需求规格说明（PLDSRS）

PLDSRS 描述配置项的功能、外部/内部接口，以及确保满足每个需求的方法。应包括：

- 全部功能需求和性能需求；
- 与软件或其他 PLDS 的交互流程、操作要求、操作时序和接口协议；
- 外部接口关系图、信号关系、时序特性和余量；
- 内部模块关系图及信号关系；
- 数据名称、大小、地址分配和读写要求；
- 资源利用预估、资源/时序余量和处理时间要求；
- 从任务书分解的安全性要求；
- 保密性需求；
- 功能完备性、可靠性、可维护性、可移植性、可重用性等质量因素；
- 数学模型、算法、芯片型号/等级、工具环境/版本、语言和方法约束；
- 每一条需求到研制任务书的可追踪性。

正文格式见附录 C。

### 5.8 可编程逻辑器件软件设计说明（PLDSDD）

PLDSDD 描述总体结构原理、功能模块设计、详细设计、验证设计和模块到需求的可追踪性。功能模块设计应标识模块及用途、设计方法、引用 IP 核及属性、算法实现、时钟域，以及可靠性、安全性、可维护性、可测试性和数据安全保密设计。验证设计应覆盖功能/时序仿真、布局布线时序、资源、接口时序、功能验证和覆盖率指标。正文格式见附录 D。

### 5.9 可编程逻辑器件软件仿真测试计划（PLDSSTP）

PLDSSTP 描述测试级别和类型、测试策略和方法、仿真测试环境、接口/功能等测试内容与测试项分析，以及测试和评审进度。方法可包括功能仿真、门级仿真、时序仿真和静态时序分析。正文格式见附录 E。

### 5.10 可编程逻辑器件软件仿真测试说明（PLDSSTD）

PLDSSTD 描述仿真测试准备、测试用例和测试过程，使需方能够评估测试是否充分。应描述测试环境，以及每项测试涉及的需求、先决条件、输入、预期结果、评价准则和测试过程。正文格式见附录 F。

### 5.11 可编程逻辑器件软件仿真测试报告（PLDSSTR）

PLDSSTR 是仿真测试记录，应包括：

- 初次测试、回归测试和总结等测试过程；
- 测试环境；
- 功能/门级/时序仿真、静态时序分析、用例执行和问题情况；
- 对需求/设计的追踪覆盖和代码覆盖率，对未覆盖语句/分支作影响域分析；
- 问题分析、全面评估、遗留缺陷/限制/约束和建议；
- 测试环境与操作环境差异及影响；
- 测试执行结果记录和问题报告单。

正文格式见附录 G。

### 5.12 可编程逻辑器件软件确认测试计划（PLDSVTP）

PLDSVTP 描述确认测试类型、方法（如实物测试）、环境、内容和进度。正文格式见附录 H。

### 5.13 可编程逻辑器件软件确认测试说明（PLDSVTD）

PLDSVTD 描述确认测试准备、测试用例和测试过程，使需方能够评估确认测试是否充分。应描述测试环境，以及需求、先决条件、输入、预期结果、评价准则和过程。正文格式见附录 I。

### 5.14 可编程逻辑器件软件确认测试报告（PLDSVTR）

PLDSVTR 是确认测试记录，应覆盖过程、环境、实物测试结果、用例和问题、追踪充分性、全面评估、遗留缺陷/限制/约束、环境差异影响、执行记录和问题报告单。正文格式见附录 J。

PLDSUD 描述适用系统和 PLD 项目，包括芯片/配置芯片型号、开发环境、配置文件版本、时钟频率和功耗、温度/器件等级/抗辐照环境、封装与管脚、通信协议和操作时序，以及器件固化流程。正文格式见附录 K。

## 附录 A（规范性附录）可编程逻辑器件软件可行性和风险分析报告正文格式

### A.1 范围

#### A.1.1 标识

描述适用系统和 PLDS 的完整标识，适用时包括标识号、名称、缩略名、版本号和发布号。

#### A.1.2 系统概述

简述系统用途、标识，以及本文档适用的 PLDS 在系统中的作用。

#### A.1.3 文档概述

概述文档用途、内容和保密性要求。

### A.2 引用文档

列出全部引用文档的文档号、标题、编写单位或作者、版本号和出版日期等。

### A.3 需求分析

- A.3.1 功能需求：分节描述 PLDS 功能需求。
- A.3.2 性能需求：分节描述 PLDS 性能需求。
- A.3.3 接口需求：分节描述 PLDS 接口需求。
- A.3.4 工作条件：描述 PLDS 所需工作条件。

### A.4 可行性分析

针对以下方面开展分析并给出结果：

- 设计资源；
- 功耗；
- 基于系统时序的工作频率；
- 防辐照方法对资源和频率的影响；
- 全部功能和非功能需求（包括降额）的可测试性；
- 适用芯片及其频率、封装、资源、温度、辐照、峰值功耗等属性；
- 设备、技术支持、设计/测试工具等基线技术要素的寿命与可用性；
- 必要人力资源；
- 第三方 IP 核的可用性、许可、支持、合法性和经济可行性。

### A.5 必要性分析

比较是否应采用 PLD 以及其他实现方案，确认采用 PLD 的必要性并给出结果。

### A.6 继承性分析

分析继承性设计的可行性和风险并给出结果。

### A.7 风险分析

标识潜在风险、预防措施和意外计划，包括采购、工具、人员、需求频繁变更、供货周期和备件等，并给出结果。

### B.1 范围
