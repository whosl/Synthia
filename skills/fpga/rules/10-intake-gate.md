# FPGA 需求入口门禁

| 属性 | 内容 |
|---|---|
| 规则编号 | SYNTHIA-FPGA-RULE-10 |
| 版本/状态 | v0.1 / candidate |
| 适用对象 | `fpga-intake` 及所有进入 FPGA 工作流的任务 |

默认策略：**凡是 FPGA / RTL / Verilog / 仿真 / 波形 / 约束 / 上板相关的工程任务，优先先走 `fpga-intake`。**

## 1. 必须先走 intake 的情形

- 用户提出 FPGA/RTL 相关工程请求，且有产出文件、修改代码、跑工具、定位错误、生成报告或交付物的意图；
- 需求含混或缺少可执行边界，例如：
  - 没有说明要新建、修改、验证还是调试；
  - 目标模块/功能不清楚，无法判断应交接哪个实现类技能；
  - 涉及板卡、引脚、约束、CDC、总线、寄存器语义、吞吐/延迟等关键工程条件，但缺少必要信息；
  - 编译/仿真/波形问题没有提供可复现的输入快照、日志、源文件或证据路径；
  - 明确要求交付审计/合规/客户级文档，但验收口径缺失。

## 2. 不要走 intake 的情形

- 用户在闲聊/科普/概念讨论，没有要产出文件、修改代码、跑工具或定位错误的意图。

## 3. 快速放行（fast path）条件

请求仍先进入 `fpga-intake`，但满足以下条件时不提问、直接产出 intake 候选产物并交接下一阶段：

- 常见、独立、低上下文任务：计数器、分频器、移位寄存器、同步器、简单 FSM、基础组合/时序数据通路、孤立 TB 生成、单点编译/仿真检查；
- 请求已给出足够的行为目标，能用合理默认端口、复位、模块名推进；
- 不涉及多模块架构拆分、协议初始化序列、CDC 策略、寄存器映射、复杂约束或板级集成；
- 未命中 `00-skill-routing.md` 第 3 节的协议时序敏感模块判定标准；若命中且关键契约未冻结，即使目标只有单模块 RTL 也不得走快速路径。

## 4. 稳定输入标准（满足越多越应快速放行）

- 明确目标与非目标；
- 明确关键约束（至少覆盖与当前任务强相关的部分：接口/协议、时钟复位/CDC、吞吐/延迟、寄存器语义、工具链边界等）；
- 明确验收口径（PASS/FAIL、波形检查点、对标规则、或可复现实验步骤）；
- 提供必要证据的最小集合：
  - 新开发：接口契约/需求来源/期望行为；
  - 修复编译：可复现的输入快照与完整工具日志证据。

## 5. 上游回退

不满足快速放行条件时，仍先走 `fpga-intake`，用最少问题补齐阻塞信息。

若后续 RTL 候选暴露出命中协议时序敏感判定标准的问题，且接口契约、协议边沿语义、相位次序、初始化步骤或命令/响应边界仍未冻结，不要把它视为"再试一次 RTL 就能解决"的同层问题；应回退到 intake/architecture/行为规格层补齐上游定义后再继续。回退动作以 Task 建议形式提出，由 Workflow Engine 推进。
