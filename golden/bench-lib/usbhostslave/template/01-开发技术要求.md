# USB 1.1 功能从设备控制器（slave-only）— 开发技术要求

- 文档编号：USB-SLV-REQ；版本 1.0（2026-10-01）
- 梯队：T3（收敛极限档）；出题卡：bench-lib/usbhostslave
- **统一器件：xc7k160tffg676-1（Kintex-7 160T，speed -1）——T3 器件统一口径**
- 规范基准：USB 1.1 规范（Universal Serial Bus Specification, Revision 1.1, 1998-09-23）。规范为权威：本文不复述其数学定义（NRZI、位填充、CRC 移位结构、包格式位序），只引用条款号并给行为要求；数据类常量见附录 `std/usb-constants.md`
- 本文独立成篇：不引用任何参考实现的结构、命名或文件组织信息

## 1. 任务概述

实现一个 **USB 1.1 全速（12 Mbps）功能从设备控制器（slave-only）** 的可综合 RTL：从 D+/D- 差分线接收/发送串行数据，完成物理层信令与数据链路处理（NRZI、位填充、同步/EOP、CRC），实现 USB 从设备协议（地址过滤、端点分路、控制传输状态机、握手响应），并对片上总线暴露寄存器/FIFO 访问接口。**主机控制器（host）侧功能不在范围内**（出题卡裁剪：82.7k 行主从树 → slave-only 子题）。

范围外（明确不做）：主机侧令牌发起、SOF 生成、挂起/恢复/远程唤醒（见 OQ-002）、高速/低速模式、集线器中继、等时端点（见 FUN-010 选项）、板级电气（上拉电阻阻值、ESD、连接器）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| FS | Full-Speed，12 Mbps |
| SIE | Serial Interface Engine：NRZI/位填充/CRC/同步与 EOP 检测的串行引擎 |
| PID | Packet ID（包标识，8 bit：4 bit 码 + 4 bit 反码） |
| 令牌/数据/握手包 | USB 三类包（token/data/handshake，规范 §8.3） |
| 控制传输 | Control Transfer（规范 §8.5.2）：SETUP→DATA→STATUS 三阶段 |
| EP | 端点（endpoint，4 bit 地址空间） |
| D+/D- | 差分信号线；J/K/SE0 三种线态（规范 §7.1.7） |

## 3. 功能需求

| 编号 | 需求 | 级别 |
|---|---|---|
| USB-DRQ-FUN-001 | **NRZI 编解码**：接收侧线态翻转→0、保持→1（规范 §7.1.8 附录 NRZI 计时图）；发送侧相反。位采样与线态恢复在位中心对齐 | 关键 |
| USB-DRQ-FUN-002 | **位填充/解填充**：发送数据域连续 6 个 1 后插入 0（规范 §7.1.9）；接收侧连续 7 个 1 判 stuff error 丢弃当前包；填充计数的起止边界=SYNC 之后、CRC 之后 EOP 之前（**CRC 计算与填充相互独立，先 CRC 后填充**） | 关键 |
| USB-DRQ-FUN-003 | **SYNC/EOP**：包首检测 8 bit SYNC（线序 KJKJKJKK，数据 0x80 LSB-first）；包尾检测 SE0×2 比特 + J×1 比特 EOP；发送侧生成同构。EOP 后回到空闲 J 态等待下个 SYNC | 关键 |
| USB-DRQ-FUN-004 | **CRC-5/CRC-16**：令牌用 CRC-5（11 bit 覆盖域），数据用 CRC-16（数据域覆盖，最大 1023 字节）；生成多项式、初值（全 1）、余数取反与发送位序按规范 §8.3.5 与附录常量；校验失败静默丢弃当前包（无响应，规范 §8.3.5） | 关键 |
| USB-DRQ-FUN-005 | **PID 译码与校验**：PID 高 4 bit 必须为低 4 bit 反码，否则丢弃（§8.3.1 表 8-1 常量见附录）；本子题需响应的 PID：OUT/IN/SETUP/DATA0/DATA1/ACK/NAK/STALL | 关键 |
| USB-DRQ-FUN-006 | **地址与端点过滤**：7 bit 设备地址 + 4 bit 端点号；地址不匹配的令牌静默忽略（§9.1.2 行为语义）；地址经 SET_ADDRESS 请求装载，复位后为 0 | 关键 |
| USB-DRQ-FUN-007 | **端点配置**：EP0 恒为双向控制端点；另有 ≥2 个可配置通用端点（方向、使能、FIFO 深度可经寄存器配置），支持 bulk/interrupt 语义；配置为 OUT 的端点收数据、为 IN 的端点发数据 | 关键 |
| USB-DRQ-FUN-008 | **控制传输状态机**（规范 §8.5.2/§8.5.3）：EP0 对 SETUP 令牌 + 8 字节 DATA0 必接受；数据阶段按 SETUP 中 wLength 收发（DATA0/DATA1 交替，§8.5.5 说...数据 toggle 语义按规范 §8.1）；状态阶段回 DATA1（零长度）；协议错/不支持的请求回 STALL；新 SETUP 中止进行中的传输并重启状态机 | 关键 |
| USB-DRQ-FUN-009 | **标准设备请求最小集**（控制传输的译码层，规范 §9.3）：至少 GET_DESCRIPTOR(Device/Configuration)、SET_ADDRESS、SET_CONFIGURATION；未实现/无效请求回 STALL。描述符内容数据由总线侧写入（常量数值不在 RTL 内硬编码语义——按字节透传即可，但 GET_DESCRIPTOR 返回的字节序与长度必须与总线侧装载的内容一致） | 关键 |
| USB-DRQ-FUN-010 | **数据缓冲与流控**：每端点独立 FIFO（深度 ≥64 字节，参数化）；OUT 端点 FIFO 满→回 NAK；IN 端点 FIFO 空→回 NAK；EP0 的 SETUP 数据不因 FIFO 状态被 NAK（规范 §8.5.3） | 关键 |
| USB-DRQ-FUN-011 | **发送数据 toggle**：DATA0/DATA1 按 ACK 交替（NAK/超时不交替，§8.5.5 数据 toggle 语义）；总线复位清为 DATA0 | 关键 |
| USB-DRQ-FUN-012 | **线态与复位检测**：SE0 持续 ≥2.5 μs 判总线复位（规范 §7.1.7.3），复位行为=地址清 0、toggle 清 DATA0、端点反初始化；J 态持续 <2.5 μs 的 SE0 按 EOP 处理不误触发复位 | 关键 |
| USB-DRQ-FUN-013 | **发送仲裁与线驱动**：握手包优先级高于数据（同一令牌的响应窗口内）；发送期间禁收（半双工）；驱动输出经三态/输出使能控制，不驱动时释放总线（输出使能信号单独引出，板级三态在片外） | 关键 |
| USB-DRQ-FUN-014 | **中断/事件报告**：复位事件、SOF 接收（时间戳可选）、EP0 SETUP 到达、收/发完成、NAK 发送——经状态/中断寄存器可读且可屏蔽 | 重要 |

## 4. 性能需求

| 编号 | 需求 | 级别 |
|---|---|---|
| USB-DRQ-PERF-001 | 系统时钟 **48 MHz 单时钟域**（USB FS 原生 ÷4 位率；不允许第二时钟域；内部位率使能自行分频） | 关键 |
| USB-DRQ-PERF-002 | **线速吞吐**：12.000 Mbps ±0.25% 平均线率下，背靠背（包间仅隔规范允许的最小间隔）连续接收 ≥64 个最大长度数据包（1023 B），**零丢包零位错**；接收有效载荷好吞吐 ≥11.5 Mbps。测量口径见 TST-002(k) | 关键 |
| USB-DRQ-PERF-003 | 时序收敛：48 MHz 约束下 WNS ≥ 0（XDC clock-only，pins 未解析按 NSTD-1/UCIO-1 豁免口径） | 关键 |
| USB-DRQ-PERF-004 | 资源预算：LUT ≤ 10000、FF ≤ 10000、BRAM ≤ 20 tile、DSP ≤ 4 | 重要 |

## 5. 接口需求

| 编号 | 需求 | 级别 |
|---|---|---|
| USB-DRQ-IF-001 | 线侧：`clk`、同步高有效 `rst`、`wire_dp_in/wire_dm_in`（2 bit 线态采样）、`wire_dp_out/wire_dm_out`、`wire_oe`（输出使能，高=驱动）、`phy_full_speed`（常量 1，FS 标识） | 关键 |
| USB-DRQ-IF-002 | 总线侧（寄存器访问）：同步单拍总线 `bus_valid`+`bus_ready` 握手、`bus_we`、`bus_addr[7:0]`、`bus_wdata[15:0]`、`bus_rdata[15:0]`。寄存器语义最小集：设备地址读写、各 EP 的 FIFO 数据口/状态（空满水位）/配置（使能+方向）、中断状态/使能、复位事件清除。地址映射自定，须在交付文档中成表 | 关键 |
| USB-DRQ-IF-003 | 线侧采样与发送时序以 `clk` 为唯一时基；`wire_oe=0` 时输出电平不定（片外三态），`wire_oe=1` 时 `wire_*_out` 有效 | 关键 |

## 6. 验证需求

| 编号 | 需求 | 级别 |
|---|---|---|
| USB-DRQ-TST-001 | 自检 TB 内建**独立主机行为模型（Host BFM）**：在 D+/D- 线级产生令牌/数据/握手（含 NRZI+位填充+CRC 编码，**期望值由 BFM 内独立参考编码器生成，不得取自 DUT**），并独立解码 DUT 的响应；失败 `$fatal` 打印场景号、包序号、字段/位偏移、期望与实际 | 关键 |
| USB-DRQ-TST-002 | 必测场景：(a) 复位确定性（复位期零驱动+释放后地址/toggle/FIFO 态）；(b) 总线复位事件检测与恢复（SE0 2.5μs vs EOP 短 SE0 不误触发）；(c) SYNC 检测与包界（含 EOP 后紧跟下包的背靠背）；(d) 位填充边界（构造 ≥6 连 1 数据与自然填充计数）；(e) NRZI 长串 0/1；(f) CRC-5/16 正确与错误注入（翻转 1 bit 判丢包静默）；(g) 地址过滤（匹配/不匹配/广播语义错误用法）；(h) 令牌-数据-握手全交互（OUT 收→ACK/NAK、IN 发→ACK 重发/NAK、toggle 交替与 NAK 不交替）；(i) 控制传输全形态（无数据/IN 数据/OUT 数据各阶段、状态阶段 DATA1、STALL 路径、SETUP 中止重启）；(j) 流控（OUT FIFO 满间歇 NAK、消费恢复不丢不重）；**(k) 线速吞吐（PERF-002 验收）：Host BFM 以 12.000Mbps 平均线率背靠背灌 ≥64×1023B 数据包，统计 DUT ACK 计数、收齐字节总数、位错数，打印 `LINE_RATE_MBPS <n>`、`GOODPUT_MBPS <n>`、`DROPPED_PKTS <n>` 行进 stdout 供 digest 判定——`DROPPED_PKTS` 非 0 或 `GOODPUT_MBPS` <11.5 即 PERF-002 判 FAIL，不得以功能场景通过替代** | 关键 |
| USB-DRQ-TST-003 | 每条需求规定验证方法并双向可追溯；终局报告附 DRQ→证据覆盖矩阵 | 关键 |
