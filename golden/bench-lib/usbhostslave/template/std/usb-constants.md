# USB 1.1 常量附录（slave-only 子题）

- 文档编号：USB-SLV-CONST；版本 1.0（2026-10-01）
- 与《01-开发技术要求》同等约束力。**权威性声明：一切以 USB 1.1 规范原文为准；本附录数值如与规范有出入，按阻塞上报操作者，不自行勘误。**（教训：jpeg 附录 A.1 缩放因子笔误事件——发现出入即冻结正确值并上报，不静默改）
- 验证口径：期望值一律由 TB 内独立参考模型按本文规则生成；本文不提供逐包数值向量（避免手抄错误），只提供结构性常量与规则

## A.1 线态与信令（规范 §7.1.7）

| 线态 | D+ | D- | 含义 |
|---|---|---|---|
| J（空闲态，FS） | 1 | 0 | 空闲/逻辑 1 的 NRZI 保持 |
| K | 0 | 1 | J 的反相 |
| SE0 | 0 | 0 | 复位（≥2.5 μs）/ EOP（2 bit） |
| SE1 | 1 | 1 | 非法（接收侧按错误处理，丢弃当前包） |

- 复位检测：SE0 ≥ 2.5 μs（§7.1.7.3）；EOP 的 SE0 只持续 2 bit time（FS 2/12MHz ≈ 166.7ns）——两者以持续时间区分
- EOP 完整形态：SE0×2 bit + J×1 bit（§7.1.9.1）；发送侧照此生成，接收侧检测到 SE0 起始即认定包数据结束（J 的恢复用于回到空闲判定）

## A.2 NRZI 与位填充（规范 §7.1.8 / §7.1.9）

- NRZI：数据 0 → 线态翻转；数据 1 → 线态保持。编码与解码互为逆
- 位填充（仅发送侧）：SYNC 之后、CRC 之后（EOP 之前）的数据流内，**连续 6 个 1 之后插入一个 0**（ stuffed bit）。填充作用域：PID、地址/端点/帧号、数据、CRC 均在填充域内（即除 SYNC 外全部）
- 解填充（接收侧）：数据流连续 7 个 1 → stuff error，丢弃当前包（静默）
- 填充与 CRC 的次序：**先对数据算 CRC，CRC 也参与填充计数**（CRC 位流作为数据进入填充器）

## A.3 SYNC（规范 §7.1.10）

- 数据域字节：`0x80`（二进制 00000001），LSB-first 上线 → NRZI 后线序 **KJKJKJKK**
- 接收侧匹配容差：末 2 bit（KK）必收，前 6 bit 允许由线扰/采样相位偏差（本文子题：完整 8 bit 匹配，容差不作要求——TB 以理想线驱动）

## A.4 位序总则（规范 §8.3.1）

- **所有多 bit 字段 LSB-first 上线**（地址、端点、帧号、数据字节、CRC 余数——注意：CRC 余数以其移位方向自然输出，见 A.5 的操作规则，不额外反转字节序）
- 字节流按出现顺序上线（如令牌 ADDR 先于 ENDP；数据字节流逐字节 LSB-first）
- 例外：SYNC 见 A.3；PID 见 A.6

## A.5 CRC（规范 §8.3.5）

| 项 | CRC-5（令牌） | CRC-16（数据） |
|---|---|---|
| 生成多项式 | G(x) = x⁵ + x² + 1 | G(x) = x¹⁶ + x¹⁵ + x² + 1 |
| 覆盖域 | 令牌的 11 bit（ADDR[6:0]+ENDP[3:0]） | 数据域全部字节（不含 PID） |
| 移位寄存器初值 | 全 1（5'b11111） | 全 1（16'hFFFF） |
| 数据进入 | 按上线次序 LSB-first 逐位移入 | 同左（逐字节 LSB-first） |
| 余数处理 | **取反后上线** | **取反后上线** |
| 接收校验 | 对「覆盖域+收到的 CRC」重算，余数 = 残差特征值（全 1 初值下正确传输的残差为固定非零特征值——实现按「对含 CRC 的完整位流重算，与同一多项式的期望残差比对」或等价的重算-比对结构，具体期望残差由 TB 参考模型按本表规则生成，不手工抄录数值） | 同左 |

- CRC5/CRC16 均不覆盖 PID；CRC16 覆盖域上限 1023 字节（FS 最大数据载荷）
- 校验失败：静默丢弃当前包（不回任何握手，§8.4/§8.3.5）

## A.6 PID 常量（规范 §8.3.1 表 8-1）

PID 字节 = 4 bit 码（低位）+ 4 bit 反码（高位），整体作为一字节 LSB-first 上线（即先发码后发反码）。

| PID | 码（4 bit） | 本子题处理 |
|---|---|---|
| OUT | 0001 | 令牌：EP 为 OUT 方向→收数据路径 |
| IN | 1001 | 令牌：EP 为 IN 方向→发数据路径 |
| SOF | 0101 | 记帧号（可选）/忽略，不得破坏包同步 |
| SETUP | 1101 | 令牌：EP0 控制传输启动 |
| DATA0 | 0011 | 数据 PID（toggle 初始态） |
| DATA1 | 1011 | 数据 PID（toggle 交替态） |
| ACK | 0010 | 主机确认我方 IN 数据 |
| NAK | 1010 | 我方流控回给主机（FIFO 空/满），或 TB BFM 对 DUT 行为的观测项 |
| STALL | 1110 | 我方协议错误回给主机（EP0 不支持请求/端点反初始化） |
| PRE/其他 | — | 本子题忽略（低速前导不在范围） |

- PID 校验：高 4 bit ≠ 低 4 bit 反码 → 丢弃当前包

## A.7 包格式（规范 §8.3.1-§8.3.4，位时间计）

| 包型 | 组成（SYNC 之后） |
|---|---|
| 令牌 | PID(8) + ADDR(7) + ENDP(4) + CRC5(5)，随后 EOP |
| 数据 | PID(8) + 数据(0..8184 = 0..1023 字节) + CRC16(16)，随后 EOP |
| 握手 | PID(8)，随后 EOP |

- 令牌后到数据包的间隔、数据后到握手的间隔：规范允许的内部包间空闲为 J 态任意长（本文 TB 按最小可分辨间隔驱动）
- 最大数据载荷：FS 8..1023 字节（0 长度合法，用于状态阶段）

## A.8 数据 toggle 语义（规范 §8.5.5 精神，控制传输 §8.5.2/§8.5.3）

| 事件 | toggle 行为 |
|---|---|
| 总线复位 | 双方清 DATA0 |
| SETUP 令牌完成 | EP0 数据阶段起点固定 DATA0（SETUP 自带的 8B 数据恒为 DATA0） |
| 数据包被 ACK | 发送/接收侧各自翻转（DATA0↔DATA1） |
| 数据包 NAK/超时/错 | **不翻转**，重发同 PID |
| 控制传输状态阶段 | 恒 DATA1（零长度数据包） |
| SET_ADDRESS 完成前 | 设备在旧地址响应完成本次传输，再切换（实现细节由 TB 场景覆盖） |

## A.9 控制传输请求最小集（规范 §9.3/§9.4）

| 请求 | 行为 |
|---|---|
| SET_ADDRESS | 状态阶段完成后装载新地址（7 bit） |
| GET_DESCRIPTOR（Device/Configuration） | 数据阶段从总线侧预载的描述符缓冲逐字节回发，长度=wLength 与缓冲长度的较小者 |
| SET_CONFIGURATION | 记录配置值，启用非零端点 |
| 其他/无效 | STALL（数据或状态阶段按规范 §8.5.2/§8.5.3 时机） |

描述符字节数据由总线侧接口预载（TB 注入），RTL 只透传——**不在 RTL 内硬编码任何描述符数值**。
