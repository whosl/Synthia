## 1. 目的与证据边界

本计划规定默认 100 MHz、9600 bit/s、8N1 配置下的需求驱动行为级验证。测试台必须在任何检查失败时 `$fatal`，仅在全部用例完成后打印最终 `PASS`。

运行分类必须明确：

- 本机 Icarus 运行只作为快速、可复现的 exploratory 交叉检查；
- XSim 结果只有在保存精确输入哈希、Vivado 版本、命令、返回码和原始日志后才构成受控工具证据；
- exploratory 成功不计入正式门禁、需求通过率或基线；
- 任何 RTL、TB、XDC 或工具配置变化都会使旧运行不再支持当前候选；
- 行为仿真不替代 CDC 静态检查、综合、实现、板级测试和人工批准。

## 3. 验证方法映射

方法：I=审查，A=分析，S=静态检查，D=动态仿真，T=板级测试。表中“规划”表示有验证路径，不表示已执行或已批准通过。

| 需求 | 方法 | 验证项/通过准则 |
|---|---|---|
| FUN-001/002 | D | CASE-01、02：tx_start 被接受，逐位观察 1 起始+8 数据 LSB first+1 停止，tx_busy 覆盖整帧，tx_done 单拍 |
| FUN-003 | D+I | CASE-01：忙期注入第二请求，首帧不变且不产生额外 tx_done；审查仅 IDLE 采样 |
| FUN-004/007、REL-002 | D+I | CASE-04、05：假起始不完成；坏停止位仅产生 frame_err，抑制 rx_done 且持续低不重触发；线路回高后的正常帧恢复 |
| FUN-005/006 | D | CASE-02、05～07：边界/跳变码型、错误帧不更新有效数据、端点波特率和连续帧的数据/脉冲检查 |
| FUN-008 | D | CASE-03：TX=C3 与独立 RX=5A 同时进行，两条数据通路分别正确 |
| FUN-009、CKR-002、REL-003 | D+I | 初始复位逐项检查；CASE-08 发送中同步复位并验证恢复后环回 |
| IF-001/003 | I+D | 顶层端口审查；CASE-01 逐位核对 LSB first 和 8N1 |
| IF-002 | D+I | 全局监视器检查 tx_done/rx_done/frame_err 仅一拍，frame_err 与 rx_done 必须互斥 |
| CKR-001 | S+I | 编译/综合结构检查：单 clk 上升沿，无门控/派生时钟 |
| CKR-003 | S+I | rxd_meta→rxd_sync 两级 ASYNC_REG；功能逻辑不得使用 rxd/rxd_meta；rxd_sync_d 仅为同步后边沿历史；正式 CDC 报告待补 |
| TIM-001 | A+D | 100 MHz/10416=9600.6144 bit/s，误差约 +0.0064%；CASE-01/02 旁证 |
| TIM-002 | A+D | CASE-01 逐位保持 10416 clk；CASE-09 起始沿间隔 ≤1,041,666 ns |
| TIM-003 | A+D | CASE-06 分别用 102,083 ns 和 106,250 ns 外部位宽验证标称 +2%/-2% 端点 |

| RES-001 | S | 综合资源：FF≤200、LUT≤300、BRAM/DSP/MMCM/PLL=0 |
| REL-001 | I+D | 3 bit FSM 保留 4 个非法码；CASE-10 注入 3'b111，检查 default 完整恢复及后续功能帧 |
| TST-001 | D | CASE-02 四个环回码型自检 |
| TST-002 | I+S | 参数表达式和计数器宽度审查；非默认参数组合属于扩展回归，不以加速参数替代默认验证 |

## 4. 动态用例

所有用例均在一个确定性测试台中执行；全局脉冲监视器和 220 位时间 watchdog 与主激励并行。

| 编号 | 激励 | 核心检查 |
|---|---|---|
| UART-TST-CASE-01 | 发送 55，第二位期间提交 AA | 起始/8 数据/停止位逐位中点检查；busy 全程有效；忙期请求被忽略；仅一个完成脉冲 |
| UART-TST-CASE-02 | 环回 A5、00、FF、3C | 四个接收值一致，无 frame_err，发送/接收均完成 |
| UART-TST-CASE-03 | 同时发送 C3、从独立 rxd 输入 5A | TX 串行帧为 C3，RX 数据为 5A；证明非同一环回字节的全双工 |
| UART-TST-CASE-04 | rxd 拉低 1/4 位后恢复高 | 不产生 rx_done/frame_err，状态机可继续工作 |
| UART-TST-CASE-05 | 输入数据 96 且停止位为低并保持一整位；线路回高、留出空闲后输入正常 69 | 错误帧仅 frame_err 单拍，rx_done 被抑制且不产生假帧；恢复帧为 69 且无错 |
| UART-TST-CASE-06 | 输入 87@+2%、78@-2% | 两个端点均正确接收且无 frame_err |
| UART-TST-CASE-07 | 12、E7 连续输入，仅保留规定停止位 | 两帧按序完成，无错、无丢帧 |
| UART-TST-CASE-08 | 发送 00 过程中施加同步复位，释放后环回 D2 | 下一时钟恢复安全值；中断帧不产生完成；释放后正常收发 |
| UART-TST-CASE-09 | 连续发送两个 FF，第二帧在空闲后立即请求 | 相邻起始下降沿间隔不超过 1,041,666 ns；当前候选期望 1,041,610 ns |
| UART-TST-CASE-10 | 分别把 TX/RX state 注入保留非法码 3'b111 | 下一拍均回 IDLE，TX 输出/忙状态安全；随后环回 4B 成功 |

### 4.1 公共检查

1. 初始复位逐项检查 txd、busy/done、rx_data、frame_err；
2. tx_done、rx_done、frame_err 不得连续两个 clk 为高；
3. frame_err 与 rx_done 不得同时有效；错误帧不得增加 rx_done 计数；
4. 所有数据比较使用四态严格比较，X/Z 视为失败；
5. watchdog 触发即失败；最终 PASS 之前不得提前 `$finish`。
