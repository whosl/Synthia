# Synthia 统一项目页功能说明（v3）

- 实现版本：v3（提交 8b81173 起的当前形态）
- 规格来源：`specs/unified-project-page-v3.md`（grill 定稿）+ `specs/ui-redesign-v1/v2.md`（分层与术语）
- 代码位置：`web/src/views/UnifiedProjectView.vue`（页面）+ `web/src/domain/`（领域逻辑）
- 路由：`/projects/:id`（旧路由 overview/artifacts/tasks/workbench/runs 全部重定向至此）

## 页面定位

一个项目一个页面：**对话与工程状态双主体**。左侧（主体）是与 free-agent 的对话工作台，顶部是常驻工程状态带，审批时底部滑出抽屉。原先的四个页面（项目总览/产物库/任务工作台/运行记录）全部并入本页。

## 布局结构

```text
┌──────────────────────────────────────────────────────┐
│ 顶部状态带（常驻）                                      │
│ 任务切换器 │ 门序列+里程碑徽章 │ 当前动作 │ 记录入口      │
├──────────────────────────────────────────────────────┤
│ 对话流（主体）                                          │
│ 用户气泡/Agent叙述/工具条/产物卡/事件卡/审批结果/打断标记 │
├──────────────────────────────────────────────────────┤
│ 消息输入区 │ 底部审批抽屉（等待批准时滑出，半屏）          │
└──────────────────────────────────────────────────────┘
```

## 功能清单

### 1. 顶部状态带

| 功能 | 说明 |
|---|---|
| 任务切换器 | 多任务（会话）并存；下拉切换对话流内容；其他任务后台继续跑；短标签取任务文案前 18 字 |
| 门序列 | G1~G9 紧凑徽章（需求审查/行为审查/设计审查/RTL审查…），状态色：已通过/等待中/未开始，hover 显示详情 |
| 里程碑徽章 | B0~B4（需求/设计/RTL/实现/发布里程碑），active 高亮 |
| 当前动作 | 一句话状态：等待批准（高亮+门名）/ 运行中（阶段+已用时）/ 终态人话 |
| 记录面板 | 状态带展开项：本项目全部工具运行（操作/状态/耗时/错误码）+ 按需展开证据清单与内容（SHA-256、文件大小）。技术级信息（L3）只在此处出现 |

### 2. 对话流（信息流）

| 功能 | 说明 |
|---|---|
| 回合制排序 | 严格按对话回合交替：用户消息右气泡 → Agent 叙述左排；回合间绝不合并（dsh/opencode 语义） |
| 流式输出 | SSE 真流式：Agent 回复逐字出现（▍游标），markdown 增量渲染（代码围栏逐行增长不重排）；markdown-stream 移植自 opencode（MIT） |
| 工具条四态 | pending 微光不可展开 / running / completed 弱化+耗时 / error 红色可展开详情 |
| 产物卡 | 候选产物登记后以卡片出现（《GJB 文档名》+候选徽章），点击右侧滑出抽屉阅读全文（markdown 渲染） |
| 门禁事件卡 | 「✓ 需求审查已通过」「⏸ 等待 G? 批准」等状态变化 |
| 打断标记 | 「直接插入」打断当前轮后，流内留打断标记卡 |
| 排队提示 | Agent 运行中发的消息显示「已排队，Agent 在当前工具结束后处理」 |
| 叙述永不折叠 | Agent 文本永远直接可见；仅 >15 行代码块折叠为代码卡（语言/行数/点击展开） |
| 失败汇报 | 对话式：Agent 陈述卡在哪+建议，无弹窗无按钮组 |
| 滚动行为 | 自动锚定底部；用户上滚（距底>80px）暂停自动滚动 |

### 3. 消息输入

| 功能 | 说明 |
|---|---|
| 常规发送 | idle 时直接 prompt；运行中默认入队（steer 语义） |
| 直接插入 | 「直接插入」按钮：abort 当前轮 + 立即以新消息重新 prompt |
| 不锁死 | 发送期间输入框始终可用；POST 立即返回 accepted（26ms 级） |

### 4. 底部审批抽屉（就地审批）

| 功能 | 说明 |
|---|---|
| 触发 | 当前任务 awaiting_approval 且对应门禁提交 in_review |
| 内容 | 待审产物列表（快照成员 →《GJB 文档名》→ 逐份可展开 markdown 阅读区，半屏高优先阅读） |
| 批准 | 里程碑门（G1/G3/G4/G7/G9）按钮写明后果「✓ 批准并建立 B? 里程碑」（baseline_id=bl-<gate>-<ts>）；非里程碑「✓ 批准」 |
| 驳回 | 理由必填，空则按钮置灰 |
| 结果反馈 | 批准后抽屉收起+流内「✓ 已批准 🏁 已建立 B? 里程碑」事件卡；驳回后「✗ 已驳回+理由」退回说明 |
| 失败人话化 | 批准失败显示人话（如「同类里程碑已存在生效基线」）+ 建议，关联号只在记录面板 |
| 自动续跑 | 批准后 Runtime 监视器自动解锁继续（无需手动 resume） |
| 复用 | Skill 进化提案走同一抽屉（UI 占位，后端另立切片） |

### 5. 空项目首屏

对话框居中（ChatGPT 新会话式）+ 示例任务卡片（如「设计一个 UART 收发器…」）一键填入；创建任务以 mode=agent 建立 free-agent 会话。

### 6. 完成时刻

任务全完成（码流+G4 批准）：流内大成功卡（码流 SHA-256/大小/证据链/下载入口）；《交付摘要》导出按钮占位（后端另立切片）。

### 7. 实时通道（SSE）

| 项 | 说明 |
|---|---|
| 订阅 | fetch-SSE（Bearer 头），随任务切换重订 |
| 事件 | part（新/定稿）/ delta（逐字）/ status / done / reset |
| 续传 | Last-Event-ID 断点续传（服务端 2000 事件保留窗） |
| 降级 | 断线指数退避重连（1s→2s→4s），3 次失败降级 3s 轮询并显示横幅「实时连接中断，已切换定时刷新」 |
| 兜底 | 3s 轮询永远并行存在（SSE 是加速不是依赖） |

## 支撑机制（页面背后）

- **数据物化**：`domain/parts.ts` 的 `auditToParts` 纯函数——audit 六类事件+产物+证据 → 时序 part 数组；回合制聚合/工具 FIFO 配对/降噪合并/终态推断，全部可单测
- **状态带推导**：`domain/band.ts`——门状态与里程碑从 gate-submissions+baselines 推导
- **流式合并**：流式定稿 part 按文本指纹原位顶替 audit 副本；在途 part 追加流尾
- **治理边界**（页面永远遵守）：批准仅 human 角色（服务端 403 兜底）；run_class 服务端裁决；候选产物全部带「候选」徽章；Agent 完成声明经声称-记录核查（说谎到不了用户）

## 已知边界（非本期）
