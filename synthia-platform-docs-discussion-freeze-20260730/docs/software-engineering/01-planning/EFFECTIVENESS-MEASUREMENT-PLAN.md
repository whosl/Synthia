# Synthia 效果评测与人工基线计划

| 属性 | 内容 |
|---|---|
| 文档编号 | SYNTHIA-PLAN-003 |
| 版本/状态 | v0.1 / 讨论冻结候选，责任人与日期待定 |
| 日期 | 2026-07-30 |

## 1. 目的

评测用于回答复杂 Agent 编排是否在相同工程目标下产生可重复的质量或效率收益。不能用 Agent 数量、生成文本数量或额外 Token 消耗代替工程效果，也不能在平台介入后补采不可恢复的人工基线。

## 2. 六类核心指标

| 维度 | 示例指标 | 证据来源 |
|---|---|---|
| 人工投入 | 分角色有效工时、修改工时、审批工时 | 工时台账、任务事件、评审记录 |
| 周转时间 | 输入冻结至候选、批准、B2、码流的时间 | 可信事件时间戳 |
| 正确性 | 需求遗漏、接口/状态语义缺陷、RTL/TB不一致 | 独立缺陷清单、评审和测试 |
| 首次通过 | G1～G9首次提交通过率，重点 G4/G5/G6 | GateSubmission 历史 |
| 人工干预 | 接管次数、修改行/项、拒绝与回退原因 | 审计事件、差异和问题记录 |
| 成果复用 | 复用成果数量、适用性错误、节省投入 | KnowledgeEntry、来源和复核记录 |

同时记录 Token、模型费用、运行费用、墙钟时间和失败重试，避免把额外计算量误认为编排质量。

## 3. RT-UART 三组对照

| 组 | 方案 | 控制要求 |
|---|---|---|
| A | 单强 Agent + 确定性工具 | 使用相同批准输入、工具和门禁 |
| B | 6 个逻辑 Agent + 受控工作流 | MVP 推荐方案 |
| C | 9 个完全独立角色 Agent | 仅用于验证额外角色分离是否有稳定收益 |

三组使用相同任务包、需求版本、器件/工具配置、缺陷注入集、知识版本和人工批准标准。顺序应随机或交叉，审批人尽可能不知道方案组别。

## 4. 质量指标

至少比较：需求遗漏率、派生需求无来源率、孤立追踪数量、注入缺陷发现率、误报率、未定义设计语义、RTL/TB不一致、关键 CDC/静态问题、人工修改量、G4首次通过率、重复运行一致性和批准后缺陷。

规划覆盖、执行覆盖和需求通过率分别统计；失败运行可计已执行，不能计通过。

## 5. 样本和重复

RT-UART 是第一样本，不足以证明亿门级、时序收敛或跨项目泛化。每组至少进行多次独立运行并固定随机种子/模型参数；具体重复次数、置信区间和后续大规模样例由评测负责人批准。没有足够样本时只报告观察结果，不声称统计显著。

## 6. 人工基线

人工基线必须在平台影响试点工程师之前采集。需确定：基线任务、参与者、操作说明、起止条件、工时记录方式、缺陷真值集、评审人、工具环境、样本保管和截止日期。开题报告中的约 20 人天、约 700 人时等数值作为待复核参考，不直接替代同任务基线。

## 7. 决策规则

默认采用 B 组作为 MVP 架构。只有 C 组在质量、重复性或人工投入上产生稳定且足以抵消成本的收益时，才把更多角色拆成常驻独立 Agent。若 A 组在相同预算下等效或更优，应简化编排但保留 Workflow、批准、追踪和证据控制。
