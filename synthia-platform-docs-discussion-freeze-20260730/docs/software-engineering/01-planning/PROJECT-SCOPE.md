# 项目范围与产品边界

## 1. 产品愿景

建设一套面向 FPGA 工程的智能体操作平台。Synthia 通过 Agent、Skill 和受控 Connector 帮助用户理解需求、生成和分析工程制品，并在授权范围内调用 Vivado 完成仿真、综合、实现和码流生成等任务。Synthia 不复制或替代 Vivado/工业软件的原生 GUI 和工程业务逻辑；用户可以不直接打开 Vivado 完成授权范围内的开发，也可以随时回到传统 Vivado 操作，Synthia 不得未经明确授权接管、修改或影响传统工程操作。未来前端可独立运行或嵌入 FPGA 工业软件的小窗/WebView。

平台面向抗辐射和大规模 FPGA 等高保证场景，但不把 RT-UART 或某一器件的特定设计规则固化为全平台默认值。

## 2. 业务目标

| ID | 目标 | 验收方向 |
|---|---|---|
| BO-001 | 提升 FPGA 工程智能化操作能力 | 用户可用自然语言或结构化任务驱动受控 Agent 完成需求、设计、验证和 Vivado 操作任务 |
| BO-002 | 提升需求到可综合设计效率 | 试点前建立人工基线，平台方式保持质量并降低投入/周期 |
| BO-003 | 提升高覆盖测试向量设计效率 | 典型任务人工投入由约 20 人天降至约 1 人天，覆盖效果不低于人工基线 |
| BO-004 | 提升 Vivado 工程操作效率 | 综合、实现、时序分析和位流生成可由 Synthia 在授权范围内编排执行、可追溯、失败可定位 |
| BO-005 | 保持传统工业软件工作方式可用 | Synthia 不复制原生 GUI；用户直接使用 Vivado 时，平台不越权接管、修改或影响其工程 |
| BO-006 | 形成组织知识资产 | 规则、案例、故障、策略、Vivado Skill 和验证结论可审查、可版本化、可复用 |

### 3.1 范围内

- 项目目标和原始需求的导入、澄清、结构化和候选管理；
- 系统需求到 PLDS 需求的分解、派生需求管理和双向追踪；
- PLDS 结构设计、详细设计候选生成及人机评审；
- RTL、IP 集成描述、约束和基础验证资产生成；
- Agent Skill、知识检索、任务编排、工程分析和结果诊断；
- 编码规则、静态检查、CDC 等质量检查；
- 通过 Vivado Connector 在授权范围内执行仿真、综合、布局布线、DRC、静态时序分析和码流生成；
- 关键操作人工审核、异常接管、全过程事件和产物审计；
- 抗辐射设计规则、问题处置、Vivado 操作方法和验证知识管理；
- Synthia Core、版本化 API、独立或嵌入式前端、本地/私有化部署和现有研发环境连接；
- 厂商无关 Connector Port、可复用 Connector SDK，以及 MCP/HTTP/Queue 可替换 Adapter；
- 独立 Linux/Windows Vivado Connector 和 Board/Lab Connector；工业软件集成仅作为受控上下文、页面和任务入口，不复制工业软件原生功能。

### 3.2 暂不承诺

- 在无人审核条件下自动发布可上星/定型的位流；
- 由大模型替代安全责任人、设计负责人、质量保证或验收方作最终判断；
- 对任意 FPGA 厂商、任意版本 EDA 工具的无适配通用支持；
- 仅凭平台运行记录自动出具权威军标符合性认证；
- 未经验证的历史知识直接进入工程基线。

## 5. 成功判据

开题报告已给出的硬判据包括：需求—设计—代码—验证追踪覆盖率 100%，严重静态检查问题和关键 CDC 问题清零；其余效率指标须先通过相同试点任务建立人工基线，再确定目标值和统计口径。

## 6. 总体架构边界

| 层次 | 责任 | 不承担的责任 |
|---|---|---|
| Synthia UI | 展示项目、需求、制品、差异、追踪、Agent 对话、任务状态、报告和人工操作；可独立运行或嵌入工业软件 | 不直接访问数据库、Vivado 或 Connector；不越权修改传统工业软件工程 |
| Workflow/Agent Runtime | Workflow 管理受控任务和阶段上下文；Agent/Skill 生成候选、规划 Vivado 操作和分析结果 | Agent 不作批准或验收结论；Skill 不绕过授权执行任意 Tcl；Orchestrator 不拥有流程真相 |
| Synthia Core/API | 持久化工程域对象、权限判定、快照、批准、追踪、运行登记和影响分析 | 不复制 Vivado GUI 或把 Vivado 命令细节放入工程业务模型 |
| Connector Port/Adapter | 提供厂商无关异步 Job 语义和协议转换 | 不保存批准事实；Adapter 不直接执行工业软件 |
| Vivado Connector Worker | 按授权调用 Vivado Tcl/API，执行仿真、综合、实现、报告、码流和原始证据采集 | 不批准需求、设计、测试通过或产品发布 |
| Board/Lab Connector Worker | 串口、激励、电源、仪器、板卡资源锁和外部证据 | 不把外部结果自动改为测试通过 |
| 传统工业软件 | 保留原生工程编辑、工具运行和调试体验 | 不因 Synthia 集成而失去独立使用能力 |

用户可以通过 Synthia 完成授权范围内的 Vivado 驱动任务，也可以直接使用传统工业软件。两种模式共享受控工程数据时，必须通过显式导入、绑定或授权建立关系；Synthia 不得因为存在集成入口而自动接管、修改或重跑传统工程操作。

Synthia 的智能体链和 Vivado 执行链可以连续协作，但不要求 Synthia 复制工业软件原生页面或业务逻辑。
## 7. 首期技术边界

- 工程模式：从头重构，旧 Synthia 只在后续明确提供时选择性复用；
- 目标器件：AMD Virtex-7 `XC7VX690T`；候选 Vivado part 为 `xc7vx690tffg1761-2`，待工具实机确认；
- RTL：优先 Verilog；允许为验证平台、厂商 IP 封装或接口需要使用 Vivado 支持的其他语言；
- EDA：以 Vivado 为第一连接器，具体支持版本和板卡待确认；
- 运行：Connector 采用异步 Job 和 `exploratory/gate_check/formal` 分类；不开放任意 Tcl；
- 协议：MCP 是可替换外部 Adapter，不是 Synthia 核心业务模型；
- 黄金参考 PLDS：可配置抗翻转 UART 控制器，现有资料见 `07-pilot/RT-UART/`；它用于模板、评测、模拟知识库和 Connector 回归，不作为平台主规格。

## 8. 两条配置空间

Synthia 平台软件与每个目标 PLDS 项目分别配置、基线化、测试和发布。平台版本、流程模板或 Agent 策略升级不得静默改变已批准项目的需求、门禁、工具配置或证据解释；项目制品也不得反向成为平台默认规则，除非经过平台级评审和批准。
