| STK-Q-003 | 平台生成成果必须经过确定性规则检查和授权人员批准，方可进入受控基线。 | 初始约束 |
| STK-Q-004 | 平台应支持本地或私有化部署，敏感工程数据不出批准的数据域。 | 边界和模型部署方式 TBD |
| STK-Q-005 | 所有关键操作应可审核、结果可追溯、失败可定位。 | 已明确；审计保留期 TBD |
| STK-Q-006 | 平台应充分复用现有研发环境，连接器不得绕过 EDA 工具授权、安全和配置控制。 | 初始约束 |
| STK-Q-007 | 同一输入和基线配置下，关键构建过程应可重现，产物应具有唯一版本和完整性校验。 | 初始约束；允许的非确定性 TBD |
| STK-Q-008 | 系统应区分事实证据、工具诊断、知识建议和模型推断，并显示其来源与置信边界。 | 初始安全要求 |
| STK-Q-009 | 第一阶段代码生成应优先输出 Vivado 支持的 Verilog，并记录所用语言版本、编码规则和工具兼容性。 | 已确认；安全编码子集 TBD |
| STK-Q-010 | 平台应以可配置 Toolchain/Target Profile 支持 Vivado 返回的合法 part，不把某一器件固化为平台级规则；首个参考配置支持 XC7VX690T。 | 候选 part：`xc7vx690tffg1761-2`，待实机查询 |

| STK-Q-012 | formal 运行只允许使用批准输入；exploratory 运行隔离；gate_check 仅绑定冻结 GateSubmission 并在快照变化时失效。 | 已冻结；具体策略见 FLOW-002/003/006 |
| STK-Q-013 | Agent 编排应保持浅层和按需启用；新增 Agent 数量或委派深度必须由可重复评测证明质量/效率收益。 | 评测见 SYNTHIA-PLAN-003 |
| STK-Q-014 | 批准、撤销、豁免和基线记录必须 append-only；Worker 不得直接写业务数据库或批准事实。 | 架构约束 |
| STK-Q-015 | 平台应采用模块化边界并允许 Connector 同时提供 MCP 与后续 HTTP/Queue Adapter，避免绑定单一 Agent 框架或传输协议。 | 可复用性约束 |

## 3. 业务指标

- 高覆盖可测性向量：典型任务人工投入约 20 人天降至约 1 人天，覆盖效果不低于人工基线；
- 需求到设计：开题报告中的传统基线约 700 人时，平台目标值待试点基线测量后批准；
- 设计到硬件：关键环节贯通，关键操作可审核、结果可追溯、失败可定位；
- 成果：1 套平台原型、3 类重点环节验证、至少 1 条黄金参考工程、1 套流程规范和 1 份效果评测报告；单 Agent、6 逻辑 Agent 和 9 角色方案的对照口径见 SYNTHIA-PLAN-003。
