## 1. 目标

数据层必须同时支持细粒度追踪、源码配置、不可变大对象、人工批准、工具运行恢复和历史基线重现。Synthia Core 是业务元数据事实源；Connector 是工具执行事实源；对象存储中的文件只有完成登记和完整性校验后才成为受控制品。

## 2. 存储分层

| 存储 | 内容 | 权威性 |
|---|---|---|
| 关系/图元数据数据库 | Project、流程、实体修订、关系、快照、门禁、批准、基线、问题、风险、ToolRun/Evidence 索引 | 业务状态事实源 |
| Git/等效配置存储 | Markdown、RTL、TB、XDC、Tcl 提案、Schema 和人类可审阅差异 | 文本/源码内容与修订事实源 |
| 内容寻址对象存储 | 日志、报告、波形、覆盖数据库、DCP、网表、码流、板测文件 | 大对象内容事实源，以哈希校验 |
| 搜索/知识索引 | 批准知识、历史库和评测集的派生索引 | 非权威，可重建 |

产品选型已决策（2026-07-31）：元数据数据库为 PostgreSQL（JSONB 存领域对象，事务保证批准/基线原子性，pg_trgm/全文检索做追踪查询）；Git/配置存储为自托管 Git 服务（支持代码审查和 CI）；内容寻址对象存储为 MinIO（S3 兼容，SHA-256 键，版本化，生命周期策略）；身份源 MVP 用平台内置（PG 用户表+Token，Schema 按 LDAP 标准字段 uid/cn/memberOf/mail 设计），D6 切换 LDAP/AD。RPO/RTO 目标 1h/1h（MVP 先做每日全量备份+实时 WAL 归档，D6 补齐流复制+热备+MinIO 跨节点复制）。容量和对账责任人待 Q-013 角色任命后指派。

## 3. 对象接纳协议

1. Core 创建带项目、Job、数据域和预期输出的 UploadIntent；
2. Worker 上传至临时/检疫命名空间并计算 SHA-256；
3. 对象服务完成恶意内容、大小、类型和完整性检查；
4. Core 或独立证据服务复算哈希；
5. Core 在一个元数据事务中登记 Evidence、Manifest、ToolRun 事件和引用；
6. 对象由临时状态转为受控可读；
7. 事务失败的对象进入孤儿清单，等待重试或按保留策略清理。

Worker 不直接写 ApprovalRecord、Baseline、GateSubmission 或业务数据库表。

## 4. 不一致处理

| 情况 | 处理 |
|---|---|
| 对象存在、元数据未登记 | 标记 orphan，禁止普通检索和门禁引用，执行对账 |
| 元数据存在、对象缺失 | Evidence 标记 `corrupt/missing`，相关结论进入 invalidated，触发告警 |
| 哈希不一致 | 隔离对象和运行，禁止覆盖原记录，登记安全/质量问题 |
| Manifest 缺少必需输出 | ToolRun 不得为 succeeded；保留部分证据 |
| Git 修订与数据库记录不一致 | 阻止快照冻结，要求重新同步和复算 |
| 知识索引漂移 | 丢弃并从批准来源重建，不影响权威数据 |

## 5. 事务与事件

业务命令和领域事件使用事务 Outbox，保证批准/基线状态与事件发布一致。Connector Job 和对象上传属于跨系统过程，使用 Saga/补偿和幂等键，不假设分布式数据库事务。每个事件包含全局事件 ID、聚合 ID、序号、发生时间、操作者/服务身份、关联 ID、Schema 版本和数据域。

## 6. 哈希和清单

- 文件采用 SHA-256；目录或制品集合使用排序规范化清单后计算清单哈希；
- ConfigurationSnapshot 固定成员修订、关系版本、流程/Gate Profile、工具/模型策略和清单哈希；
- ApprovalRecord 固定被审快照、检查结果和决定内容哈希；
- Baseline 固定 ApprovedGateResult、成员、关系快照和批准记录；
- 码流包同时记录文件哈希、输入实现、part、工具版本、strategy 和生成 ToolRun。

## 7. 权限与数据域

查询和下载按项目、角色、数据域和用途授权。数据域标签从来源向派生制品、TaskPackage、JobRequest、日志和证据继承；降级或跨域必须有专门批准。对象 URI 使用短期授权或服务间身份，不在 Agent 上下文和审计摘要中暴露存储凭据。

## 8. 备份、恢复和删除

批准记录、基线、门禁提交、运行事件和证据清单禁止普通物理删除。备份必须覆盖 PostgreSQL 元数据、Git 引用、MinIO 对象清单和密钥/身份配置，并定期执行一致性恢复演练。RPO/RTO 目标 1h/1h：MVP 阶段实现每日全量备份 + 实时 WAL 归档（最低保障）；D6 产品化阶段补齐 PostgreSQL 流复制 + 热备 + MinIO 跨节点复制。保留期：受控记录禁止删除；其它按项目保留策略。具体灾备拓扑在 D6 部署架构批准时闭合。
