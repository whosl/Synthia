# Web 前端审查与重构记录

验收日期：2026-09-05 至 2026-09-06。范围：Synthia 的 Vue 前端，重点为业务操作闭环、异常恢复、现代视觉和移动端体验。

## 已修复问题

| 优先级 | 原问题及影响 | 修复结果 |
| --- | --- | --- |
| P1 | 编辑器读取和保存缺少请求身份校验，切换文件后旧响应可能覆盖新文件 | `use-editor-content` 按加载代次隔离响应；读取失败不开放空文件保存；保存失败保留编辑内容 |
| P1 | Markdown 只有预览，但界面存在保存概念；离开文件时没有未保存保护 | 接入 Monaco 的 Markdown 编辑/预览切换；保存确认后清除修改标记；文件、版本、任务和页面切换均检查未保存内容 |
| P1 | 概览沿用旧阶段推断，可能与工程工作区的 G0–G4 状态矛盾 | 使用经过验证的 Core 流程定义和项目流程状态；验证失败显示不可用，不伪造进度 |
| P1 | 概览吞掉接口错误，审批跨项目加载任一失败导致整体不可用 | 独立聚合任务、审批和流程状态，保留可用事实，提示不完整范围并提供重试；自由项目不请求工程审批 |
| P1 | 新建项目重试重新生成项目 ID 和幂等键 | 相同表单的一次创建尝试保留请求体、项目 ID 和幂等键，避免不确定网络结果下重复创建 |
| P1 | URL 查询更新导致整个工作区重挂载；写操作可能只等到旧一轮刷新 | 路由按路径保留实例，显式同步任务及审批深链；刷新队列确保写入后等待下一次刷新 |
| P2 | 发送前清空输入、移动端对话栏卸载、切任务会丢失草稿 | 项目按任务持有草稿；仅服务端确认发送成功后清空；发送失败可原文重试 |
| P2 | 登录在校验前保存凭证，失效登录丢失原页面 | 校验成功后保存；失效会话携带原路径返回登录，登录后只允许回到本地应用路径 |
| P2 | 终态永久停止轮询，后续任务或退化的实时连接难以恢复 | 保留轮询调度，页面不可见或无活动任务时跳过请求，活动和错误状态下刷新 |
| P2 | 入口页面继续引用已删除样式，布局与组件风格不一致 | 重做登录、项目台、新建弹窗和审批中心；统一导航、图标、表单、状态、空态和错误反馈 |

## 结构与交互

- `PageShell` 与 `portal.css` 统一入口页面：暖中性色、陶土色强调、清晰留白与层级；支持浅色、深色和移动端布局。
- `project-overview` 集中聚合和验证概览事实，`use-project-overview` 管理加载、刷新与卸载。页面主要负责呈现和导航。
- `CreateProjectDialog` 使用原生模态对话框，具备焦点约束、Escape 关闭、显式项目类型、流程加载失败提示和重复提交保护。
- `WorkspaceWelcome` 提供新项目的任务入口和文件浏览引导；移动端对话栏有明确关闭操作。
- `api/service` 将 API 实例与应用启动分离，避免视图依赖入口模块。
- 编辑器只读判断考虑共享工作区中仍在运行的主任务。正式审批、流程验证和交付规则继续由 Core 决定。

没有修改数据库结构、API 协议或环境变量约定；改动位于 Web 和本审查资料中。

## 仍需关注

1. 根级类型检查的错误来自未改动的 Core/Connector 源码，包括 Core `rootDir` 引入 Connector 文件、已不存在的类型导出、重复导出，以及 `structuredClone` 直接传给 `map` 的类型不兼容。Web 类型检查独立通过。此次未扩展到后端类型重构。
2. 根级测试有 339 项跳过；这些结果不能替代依赖外部数据库及其他集成环境的验收。未执行真实 Core/Runtime/Vivado 的正式审批、运行和交付闭环。
3. 现有离线 Mock 尚不支持在新创建项目中启动 Agent，接口返回 `mock_unsupported`。前端提供可理解的失败反馈；完整 Agent 体验需预置演示项目或真实后端。
4. 验收浏览器已有的 PWM 演示项目含不一致的历史流程数据。页面显示“正式流程状态”加载失败，并保留其余项目信息；未修改存储来掩盖异常。
5. Monaco 懒加载 chunk 约 3.33 MB，gzip 约 855 KB，构建仍发出体积提示。此次未将完整编辑器换成精简语言构建。
