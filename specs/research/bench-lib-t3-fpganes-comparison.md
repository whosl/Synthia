# NES PPU 渲染子系统（T3 fpganes）：黄金基线 vs 盲测对比报告

- 设计：fpganes PPU 子题（出题卡裁剪：仅 PPU——6502/APU/mapper 不在范围）
- 项目：p37（黄金基线）/ p38（盲测，用户消息式输入）
- 日期：2026-10-14 ~ 10-15；器件统一 xc7k160tffg676-1（160T，50MHz 单时钟域 ÷4 时钟使能）
- 需求：NES-PPU-REQ v1.0 + nes-ppu-constants.md（寄存器协议/loopy 滚动/精灵渲染/精灵 0 命中/NTSC 341×262/(k) FRAME_DOTS≤89342+PIXEL_ERR=0）
- 终态：双侧四步全绿 + 双侧 DRQ 覆盖矩阵 + 模板三处附录勘误被双侧暴露（保险丝机制连环生效）

## 一、双侧四步终态

| 步 | p37 黄金（fpganes ppu.v 708 行+适配层） | p38 盲测（从零 7 件） |
|---|---|---|
| validate | ✅ | ✅ |
| simulate | ✅ 场景 a..k 全过（FRAME_DOTS=89342 / PIXEL_ERR=0 / SPRITE0_DOT 实证） | ✅ **11/11 PASS**（FRAME_DOTS=89342 / PIXEL_ERR=0 / SPRITE0_DOT=11） |
| (k) 指标 | 89342 / 0 / 实证 | 89342 / 0 / 11 |
| synthesize | ✅ LUT 542 / FF 393 / BRAM 0 / DSP 0 | ✅ 0E/0CW/0W；LUT **837** / FF **201** / BRAM 0 / DSP 0 |
| implement | ✅ WNS +13.549（routed LUT 534） | ✅ **WNS +11.017**（DRC 仅豁免类） |

## 二、面积/时序对照（同 160T 同 50MHz dot rate）

| 维度 | 黄金 | 盲测 | 差 |
|---|---|---|---|
| LUT | **534**（routed） | 837 | **黄金小 1.57×** |
| FF | 393 | **201** | 盲测小 1.95× |
| DSP/BRAM | 0 / 0 | 0 / 0 | 同（全分布式） |
| WNS | +13.549 | +11.017 | 双侧大裕量（50MHz÷4 后 dot 域极宽松） |
| RTL 行数 | 1,619（参考 708+适配+compat） | 1,100 | 盲测省 32% |

**形态**：互有胜负但差距都不大（LUT 1.57× vs FF 1.95×）——PPU 是状态机+存储型设计，两侧实现风格差异（黄金参考的移位器组织 vs 盲测的组合提取式）导致的正常离散。时序双侧都是大裕量（÷4 降频后关键路径极短），无鉴别力。

## 三、覆盖对齐程度

- 双侧 DRQ 矩阵齐全（p37 27 行/p38 收官报告中），全部达标
- **判卷不同卷**（与 USB 案同构）：两侧 TB 均为独立软件渲染模型+独立场景集，但验收面同源（附录 A + (k) 三指标）——**像素逐点比对+FRAME_DOTS 双锚**使两侧的"全绿"语义比 USB 案更接近同卷（帧级等价而非仅寄存器面等价）
- 交叉验证未做

## 四、模板勘误（本件特有——保险丝连环三击）

| # | 勘误 | 暴露侧 |
|---|---|---|
| D15 | PPUMASK 位序写错 | 黄金侧四步（参考实现与附录冲突） |
| D16 | 像素窗相位换算错（"点 1-256、x=点-1"应为"点 0-255、x=点号"） | 黄金侧四步 |
| IF-003 残留 | D16 勘误时漏改的一行 | **盲测复述关**（B-7） |
| B-6 | A.4"每点自增"与 8 点平铺周期矛盾 | 盲测复述关 |

**方法论发现：盲测的复述关卡是需求缺陷的第二个暴露面**——黄金侧暴露"参考实现↔附录"冲突，盲测复述暴露"附录内部"矛盾。两侧都用"阻塞上报不自行勘误"处置，裁定权留操作者。

## 五、制作成本与过程

|---|---|---|
| 墙钟 | ~1.5 天（10-14 20:00 → 10-15 09:00，12 轮 TB 收敛） | ~1 天（10-15 09:15 → 22:00，25+ 轮收敛） |

| TB/模型 | 模型缺陷为主（象限坐标/四窗镜像/精灵地址公式 MBG 族） | 模型 M5 族（对角采样/求值窗/X 污染）+ TB T6 族（mask 激励空转/判别性/配对损坏） |
| 发射事故 | TB 落盘截断 1 次 | **5 次**（全部"良本在手就地作废重发"处置，零进度损失） |

## 六、关键发现

1. **像素流比对是强判卷面**：逐点 COLOR 比对+首失配坐标+DBG 取证使 25 轮收敛中每轮都能把残差定位到"单像素单字段"级——与 USB 的包级、msp430 的指令级相比，PPU 的像素级是粒度最细的判卷
2. **激励判别性缺陷是 TB 新缺陷类**（T6-D1/T6-N1：mask 写错使检查空转通过、负例前提不成立）——判卷面再强，激励无判别力就是假绿。两侧都自查出了这类问题
3. **发射事故成为高频事件**（p38 五次）：GLM 在长文件全文重写时的文损率显著——"外科手术式修改而非全文重写"+"良本在手作废重发"是有效的工程对策
4. **参考实现的适配层仍是最薄弱环节**（p37 唯一 RTL 缺陷在适配层；p38 的综合级缺陷也是顶层双驱/方向）——顶层接线的静态自审（D9 六查）值得进技能模板

## 七、T3 四件终局汇总

| 设计 | 类型 | 盲测 vs 黄金 | 特色发现 |
|---|---|---|---|
| jpegencode | 数据通路+吞吐 | DSP 1/17（吞吐对齐后仍 6×）；70T vs 160T | 吞吐-面积权衡曲线；不可达主张被驳 |
| usbhostslave | 位级协议 | LUT 2.17× / FF 0.56× 互有胜负 | 对齐边界地图（3 面/3 簇/4 项边界） |
| openmsp430 | CPU 核 | **双维全胜**（LUT −23.7%/WNS 2.3×） | 控制密集型是模型主场 |
| fpganes | 视频渲染状态机 | LUT 1.57× vs FF 1.95× 接近 | 像素流=最强判卷面；复述关=第二保险丝 |

**T3 横向结论**：对比形态由设计类型决定——数据通路型比吞吐代价、协议型比鲁棒性边界、控制型比密度、渲染型比像素等价。模型在四类上全部达到"同考卷四步全绿"，无一失手；差异只在资源和路径。
