# USB 1.1 从设备控制器（T3 usbhostslave）：黄金基线 vs 盲测对比报告

- 设计：usbhostslave slave-only 子题（出题卡裁剪：82.7k 行主从树 → slave-only）
- 项目：p31（黄金基线）/ p32（盲测，用户消息式输入）/ p34（交叉验证实验）
- 日期：2026-10-01 ~ 10-12；器件统一 xc7k160tffg676-1（160T 口径，48MHz 单时钟域）
- 需求：USB-SLV-REQ v1.0 + usb-constants.md（同一份考卷，含 (k) 线速场景——H34 教训落地件）
- 终态：**双侧四步全绿 + 交叉验证对齐边界地图**（p34）

## 二、规模与结构

| 维度 | 黄金 | 盲测 |
|---|---|---|
| RTL 行数 | **9,446**（slave 裁剪集 37 文件，参考原样零改动） | **2,291**（8 文件自研）——4.1× |
| 顶层封装 | usb_slave_golden_top（双时钟合并 + 8bit wishbone→16bit spec 总线桥，自研适配层） | usb_top（原生 IF-002） |
| TB 行数 | 2,972（5 文件） | 2,121（4 文件+vh） |
| 寄存器映射 | 字节地图（EPn_CTRL 0x40+4n…0xE0；READY 一次性武装） | 16bit 自定表（register_map.yaml；无 READY 机制） |

## 三、面积/时序/线速对照（同 160T 同 48MHz）

| 维度 | 黄金 | 盲测 | 差 |
|---|---|---|---|
| LUT | 1,183 | 2,571 | **2.17×**（盲测大） |
| FF | 1,417 | 792 | **0.56×**（盲测小） |
| DSP/BRAM | 0 / 0 | 0 / 0 | 同 |
| WNS | +15.973 | +10.887 | 双收敛（48MHz 门槛极低，slack 无鉴别力） |
| 好吞吐 | 11.85 Mbps | 11.77 Mbps | 双过 ≥11.5 门线 |

与 jpeg 案（17× DSP 差）形态完全不同：USB 无 DSP，比的是控制逻辑密度——**LUT 与 FF 互有胜负**（黄金三寄存器流水 getPacket 吃 FF、组合译码省 LUT；盲测以小 LUT 换大 FF 分布）。结论：**面积优势方向依设计类型而变，模型没有单一的面积极性**。

## 四、制作成本与过程

| 维度 | 黄金（p31） | 盲测（p32） |
|---|---|---|
| 墙钟 | ~1 天（10-01 23:30 发车 → 10-02 07:00 收尾） | 10.7 天墙钟（10-01 23:59 → 10-12 17:44），其中 5 天无人推进静默 + GLM 停等 + 主机重启；**活跃 ~4-5 天** |
| RTL 改动 | **参考零改动**——全部调试在 TB 侧（11 轮：BFM CRC 取反口径、blen 含 PID 偏一、READY 一次性语义、XSim i[7:0] 部分选择病灶、VBUS 边沿判据） | **13 个 DUT 真缺陷**修复链 + ~10 处 TB 自纠 |
| 关键根因 | — | 末位胞被 EOP 抢跑吃掉；S_DAT bits_left 字节回绕 31；EOP 竞态+交付偏移+CRCL 泄漏；CRC16 残差 0xB001；CRC5 比对位序；**FWFT 写后读竞态（(k) 50% 字节错之谜）**；**填充计数器 b0 双计（0x5F 位型触发、0xFF 自补偿掩蔽——全部历史观测零矛盾）**；SETUP 漏 ACK；状态阶段 STALL 提前；无条件填充三方对齐 |

| 生成事故 | 无 | 3 例生成失控（截断/乱码）触发自停 + 1 例**登记后自查截获自身补丁缺陷**（v6 转换沿丢 CRC 首位——"先修再战"） |

## 五、交叉验证对齐边界地图（p34，2026-10-12）

黄金 TB × 盲测 DUT（总线适配 shim 翻译两侧寄存器映射；场景/BFM/判据零变更）：

- **总判分 PASS=2 / FAIL=179，全部 FAIL 逐簇归位，零未解释判据**
- ✅ **已证对齐（3 面）**：中断 masked 视图；地址过滤+IN 握手；配置总线端到端
- ⚠️ **线域未收敛（3 簇，shim 自证清白后移交 DUT 侧）**：①OUT/SETUP 线侧 ACK 缺失（DUT 内部锁存 SETUP/DONE 位但握手不出线——在自有 TB 里 ACK 全对，指向 BFM 时序/组包敏感差）②总线复位事件不可观测 ③IN 载荷内容不符
- ⛔ **架构语义边界（4 项，需求允许、永久存在）**：EP0 SETUP 路由（寄存器路径 vs FIFO 路径，线侧无翻译面）；READY 一次性武装 vs 无此机制；复位事件位序；toggle 归属

**方法论结论**：需求层双绿 ≠ 线级互换。交叉验证把"对齐"从二值问题变成边界地图——三个未收敛簇正是"同一份规范、两种合规实现"的真实分歧带（鲁棒性差异），本身是 T3 的高价值数据。

## 六、关键发现（T3 数据点）

1. **功能两阶段特征复现**：模型从零实现 USB 协议栈的功能收敛弧线与 p28（JPEG）同构——先全链死（公共闸门类根因）→ 逐面复活（令牌→数据→控制传输）→ 精确位型缺陷收尾（0x5F/自补偿掩蔽）。位级取证能力（VCD 分页解剖）是破案主力
2. **两次"计数陷阱"教训**：变沿计数≠胞数（NRZI 同值并胞）；百分比指纹（50.007%）直指对称性缺陷（FWFT 读写竞态）——模型展现了从统计指纹反推机制的能力
3. **无可能性主张**：本轮模型未出现 p28 式"物理不可达"误判；判别性实验设计（预测-证伪）贯穿全程
4. **黄金侧价值再次验证**：参考 RTL 零改动通过全部验证——FreeCores 裁剪集质量过硬；黄金侧成本全在 TB（判卷难于答卷）
5. **(k) 场景实战价值**：线速三指标在两侧各暴露一个度量面缺陷（黄金 LINE_RATE 口径、盲测令牌胞漏项+32 位回绕），证明"性能指标必须机器可判定且度量面本身要被验证"

## 八、时间口径（双记）

- 黄金侧：~1 天墙钟（含 TB 11 轮调试）
- 盲测侧：墙钟 10.7 天；剔除 5 天无人推进、GLM 停等（每日楔死多次）、主机重启与部署窗口，**会话活跃 ~4-5 天**。若在正常模型供给下（无停等时代），按各轮实际推进密度估计 **~2-3 天**可完成同弧线

## 九、结论

usbhostslave 五步闭环（需求→黄金→盲测→交叉→报告）完成。T3 第二件的核心数据：**同一份考卷，模型用 1/4 的代码量达到同等功能/线速/时序达标形态；面积方向依设计类型而变（本件 LUT 2.17×/FF 0.56×）；线级互换存在明确的、可地图化的边界**。黄金参考的质量（零改动全绿）与盲测的收敛能力（13 缺陷全定位修复+多次自我证伪）都经住了交叉验证的检验。
