# JPEG 编码器（T3 p28）：从第一版到时序优化的完整路径

- 项目：p28（bench-lib T3 jpegencode 盲测，用户消息式输入）
- 日期：2026-09-26 ~ 09-30
- 模型：GLM-4.6（64k 输出预算，平台断言窗口 200k/触发 0.7，真实窗口 1M）
- 器件：xc7k70tfbv676-1（Kintex-7 70T，speed -1）
- 目标：100 MHz、LUT ≤ 30000、FF ≤ 25000、BRAM ≤ 40、DSP ≤ 80

### 第二阶段：时序优化轮（09-29 ~ 09-30，约 1 天）

**起点**：implement 失败，WNS = **-7.417 ns**（fmax ≈ 57 MHz），FF = 30,988（超预算 +5,988），BRAM = 0。

| 轮次 | 改动 | WNS | FF | 备注 |
|---|---|---|---|---|
| 基线（v3 设计） | — | **-7.417** | 30,988 | 最差路径：u_dct/hbias 7×DSP 级联 11 逻辑级 |
| 第二轮 R12-R15 | blk_assembler v4 BRAM 化 + fdct8x8 v4 乘积寄存+平衡树 | **-2.338** | 31,117 | +5.079ns 改善；BRAM 推断未生效（FDRE 阵列仍在） |
| 第三轮 R16-R23 | v7 全面优化（BRAM 属性+DSP 流水+关键路径拆分） | **+0.039 (setup)** / **-0.581 (hold)** | **6,066** | FF -80.5%；BRAM RAMB18×3 推断成功；hold 违例为 BRAM 写端口 |

**功能保持**：所有轮次功能断言零变更、23 PASS 全绿、$finish 时刻逐字节复现（预注册签名比对）。

## 优化路径的结构分析

### 模型做了什么（正确的架构决策）

| 优化 | 具体改动 | 收益 |
|---|---|---|
| DCT 乘积寄存 | V/H 两簇各加一级乘积寄存 + 3 级平衡加法树（替代左结合链） | 关键路径从 11 级逻辑降至 ~5 级 |
| BRAM 推断 | 行缓冲 `(* ram_style = "block" *)` + 写使能结构调整 | FF 从 30k 降至 6k（-80.5%），推断 RAMB18×3 |
| hbias 加法链拆分 | 7×DSP 输出从组合级联拆为流水 | setup WNS 转正 |
| 背压链重构 | 全链 skid buffer 从 2 深调至 1 深+门控优化 | 流水不阻塞同时减少 FF |

### 模型没做到什么（需要更多轮次或人工介入的）

| 遗留 | 状态 |
|---|---|
| BRAM 写端口 hold 违例（-0.581ns） | 修复中（最后一步） |
| 部分模块的 FF 推断策略（mem FDRE 阵列） | 第三轮已大部分解决 |
| DSP48E1 内部寄存器配置 | 模型选择了外部流水线（更保守） |

## 关键发现（T3 差距形态数据）

1. **模型的面积效率远高于参考实现**：16k 行参考 vs 2k 行自研实现同等功能——参考的三并行流水线用 240 DSP 和 47k LUT，模型用 23 DSP 和 13k LUT
2. **模型的时序优化是渐进式的**：-7.4 → -2.3 → -0.6 → 趋近 0——不是一次性解决，而是逐轮定位+修复
3. **功能正确性与物理优化可分离**：所有 23 个功能场景在每一轮优化后都保持全绿——模型能保持功能不变式的同时改微架构
4. **BRAM 推断是 FF 优化的关键**：从 31k FF 降到 6k 不是通过减少逻辑而是通过让综合器推断 BRAM——模型知道这个概念但需要多轮才能正确触发推断
5. **hold 违例是最后的绊脚石**：setup 先转正，hold 留在最后——这与人工时序收敛的经验一致
