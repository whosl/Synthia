# Synthia Web UI 重设计规格（v2：四项修订）

- 状态：草案，待项目负责人确认
- 日期：2026-08-13
- 上游：`specs/ui-redesign-v1.md`（信息三级分层、术语表、验收标准仍然有效，本规格为增量修订）
- 调研依据：opencode 对话信息流调研（anomalyco/opencode v1.18.18，packages/schema/src/v1/session.ts 等）

## 1. 项目列表为主页面（确认项，无需改动）

现状已满足：`/` 重定向 `/projects`。**保留现有样式不动。**

## 2. 「基线」全面改名「里程碑」

- UI 内所有面向用户的「基线」字样改为「里程碑」：基线徽章 → 里程碑徽章；「批准并建立需求基线」→「批准并建立需求里程碑」；B0~B4 映射改为：B0 需求里程碑、B1 设计里程碑、B2 RTL里程碑、B3 实现里程碑、B4 发布里程碑。
- 代码内部标识符（baseline_id 等 API 字段、变量名）**不改**——只改用户可见文案。
- v1 术语表同步更新。

## 3. 产物库按 GJB 正式文档名展示，内容全中文

背景：FPGA 按 PLDS 管理，适用 GB/T 33781-2017。产物库每条对应一份 GJB 正式文档，展示名按下表（`web/src/domain/artifacts.ts` 统一维护映射）：

| ArtifactType（内部） | UI 展示名（GJB 正式文档） |
|---|---|
| DEVELOPMENT_REQUIREMENTS | 研制（开发）技术要求 |
| SYSTEM_REQUIREMENTS | 系统需求规格说明 |
| PLDS_SRS | PLDS 需求规格说明 |
| ARCHITECTURE_DESIGN | PLDS 结构设计说明 |
| DETAILED_DESIGN | PLDS 详细设计说明 |
| CONSTRAINT_DESIGN / XDC_CANDIDATE | PLDS 接口与约束设计说明（草案） |
| RTL_SOURCE_SET | PLDS 源代码（RTL） |
| TB_SOURCE_SET | PLDS 验证环境源代码 |
| SYNTH_RESULT | 综合报告 |
| IMPLEMENT_RESULT | 布局布线（实现）报告 |
| DRC_REPORT | 设计规则检查（DRC）报告 |
| STA_REPORT | 静态时序分析报告 |
| POWER_REPORT | 功耗分析报告 |
| BITSTREAM_PACKAGE | PLDS 码流（固化）包 |
| 其余类型 | 按 ARTIFACT-CONTRACTS.md 中文名列出，未映射类型显示中文通用名「工程文档」 |

- 产物内容渲染全中文：若 LLM 产出英文标题/段落属正常（模型行为），**UI 层负责标题栏、状态、分组名全中文**，文档正文不强求翻译。
- 产物预览页头部显示：《文档名》+ 版本 + 状态（候选/已冻结）+ 生成时间。

## 4. 任务工作台对话窗格：改为信息流（按 opencode 模式）

### 4.1 数据组织

- 以「一次任务」为一个 turn：用户指令是 user 消息（右侧气泡，显示用户原话与时间）；其后 Runtime 产生的全部内容属于 assistant 信息流（左侧）。
- 信息流由 **part 数组**按时间序组成，前端按类型分派渲染，**不重排**。part 类型由 audit 事件 + docs + evidence 映射（见 4.2）。
- Runtime 服务 GET /tasks/:runId 已返回 audit（带 seq）+ docs + evidence，前端据此物化 part；现有 3s 轮询不变，渲染端按 seq 增量插入。

### 4.2 part 类型与渲染规则

| part | 来源 | 渲染 |
|---|---|---|
| 文本叙述 | model 类事件（ narrateAuditEvent 的中文句） | 普通段落气泡 |
| 工具调用 | tool_call 事件（validate_sources/simulate/synthesize/implement） | **单行工具条**：图标 + 中文标题（「编译检查」「仿真」「综合」「实现并生成码流」）+ 右侧耗时；进行中=流光动画且不可展开；成功=弱化色 + ✓；失败=红色 + 点击展开人话原因 |
| 门禁 | gate 事件 | 单行工具条特化：「需求审查评估中…」→「已通过」/「未通过」（失败红色可展开）；等待批准=「等待人工批准」标记 |
| 产物文件 | docs 登记事件 | **文件卡片**：文档图标 + 《GJB 文档名》+ 候选标签，点击在右栏预览 |
| 证据摘要 | evidence 收集 | 不内联全文；标题行显示「N 项证据」，点击去运行记录页 |
| 治理提示 | awaiting_approval | **双通道**（opencode PermissionPrompt 模式）：信息流内留一个标记 part + 页面顶部固定横幅（去审批按钮），横幅在批准前一直悬挂 |
| 生命周期 | lifecycle（心跳/重连） | 默认**隐藏**（HIDDEN 集合）；仅在运行记录页可见 |
| 循环/终态 | loop 事件 | 完成=绿色成功卡（「全流程完成，码流已生成」）；失败=红色错误卡（左红边，人话原因 + 运行记录链接） |

### 4.3 降噪规则

- 连续的低信息量事件（证据采集、只读查询）合并为一行「正在收集证据 · N 项」，可展开；
- lifecycle 心跳/重连类一律不在信息流显示；
- 空文本 part 不渲染。

### 4.4 视觉

- 用户消息右对齐蓝色气泡；assistant 内容左对齐无气泡（信息流贴左）；
- 工具条单行高度统一，图标区分类型（文档/工具/门禁/证据）；
- 每个工具条右侧显示耗时（如「12s」）——审计场景保留，opencode TUI 不显示但我们显示。

## 5. 验收标准（增量，v1 的仍然有效）

1. UI 用户可见文案中「基线」出现 0 次（grep 渲染模板层断言）；「里程碑」映射完整。
2. 产物库分组名与条目名全部为上表 GJB 文档名；未映射类型显示「工程文档」。
3. 对话窗格是 turn 式信息流：用户指令气泡 + assistant 流（叙述/工具条/文件卡/门禁条按时间序）。
4. 工具调用四态视觉：进行中流光不可展开、成功弱化、失败红色可展开、耗时可见。
5. lifecycle 事件不出现在信息流（测试断言）。
6. 等待批准双通道：流内标记 + 顶部固定横幅，批准后横幅消失。
7. build 零错误；全部测试（含新增信息流映射测试）通过。

## 6. 非目标

- 不做流式输出（轮询 3s 不变，SSE 留待后续）；
- 不做 reasoning/思考过程展示（当前模型协议未暴露）；
- 不做工具输出全文内联（全文在运行记录页）；
- 不改 API 契约。
