# Synthia Web UI 重设计规格（v1）

- 状态：草案，待项目负责人确认
- 日期：2026-08-13
- 范围：现有四个页面 + 任务工作台的信息架构与交互重设计；不改技术栈（Vue3+Vite+Pinia）、不改 API 契约
- 上游：`synthia-platform-docs-discussion-freeze-20260730` 冻结包；本规格为特性级 spec，验收以本文为准

## 1. 问题陈述

当前 UI 由功能契约驱动开发，缺少视觉/交互规格约束，导致：

1. **技术内容外溢**：jobId、SHA-256、错误码、audit 事件流直接暴露在主界面；
2. **任务工作台对话区偏移初稿**：初稿设计是「用户指令 + Agent 进展的普通话叙述」，实现成了技术事件流水账（`gate/validate_sources gate ok (vivado-batch-1) ok` 这类内容不该出现在用户视野）；
3. 用户需要工程背景才能读懂界面，违背「用户不需要理解平台内部机制」的产品定位。

## 2. 用户角色

| 角色 | 在 UI 里做什么 |
|---|---|
| 工程师（主要角色） | 发起任务、看进展、看产物、拿到码流和报告 |
| 审批者（质量/管理） | 在门禁点审阅候选产物、批准或驳回 |

**已确认（2026-08-13）：两个角色是同一个人。** 因此需要「我的待办」聚合：等待我批准的审查 + 我正在跑的任务，放在项目列表页顶部或首页，一处看清「现在需要我做什么」。

## 3. 设计总原则：信息三级分层

| 级别 | 内容 | 默认状态 |
|---|---|---|
| **L1 用户语言** | 需求、结论、等待你批准、码流已生成、失败原因（人话） | 默认可见 |
| **L2 工程语言** | 阶段名（需求分析/架构设计/仿真/综合/实现）、产物文档、报告 | 默认可见但不强调 |
| **L3 技术语言** | jobId、SHA-256、错误码、audit 事件、API 细节 | **一律收进二级「运行记录」页**，主页面不出现（连折叠区都不放） |

硬规则：**L3 内容永远不得出现在主页面**（工作台/总览/审批中心连折叠区都不设）。这是本次重设计的第一验收点。
已确认（2026-08-13）：技术细节不做折叠区，统一收到二级页面。

## 4. 逐页规格

### 4.1 登录页

- 用户目标：进入系统。
- 默认可见：Logo、Token 输入框（带「找管理员索取」提示）、登录按钮。
- 不该出现：任何错误码原文；登录失败显示「Token 无效或已过期，请核对后重试」。

### 4.2 项目列表 /projects

- 用户目标：找到我的项目，知道它进展到哪；**创建新项目**。
- 默认可见：「我的待办」聚合条（等待我批准的审查 + 我正在跑的任务，置顶）；项目卡片/表格：项目名、**当前阶段的人话描述**（如「架构设计审批中」而非「G3 in_review」）、最近活动时间。
- **「新建项目」按钮（页面右上，主要按钮样式）**：对话框只需输入项目名称（必填）；其余字段服务端缺省（分类 D1、目标器件取项目默认 xc7k70tfbv676-1 预填可改）；创建成功直接进入项目总览。
- 隐藏：项目 ID、分类标签等技术字段进详情页或高级视图。

### 4.3 项目总览 /projects/:id

- 用户目标：一眼知道项目走到哪、下一步等什么。
- 默认可见：
  - 阶段泳道（G0~G9 显示为**中文阶段名 + 状态图标**：需求/行为规划/架构设计/RTL实现/实现与码流…；状态：未开始/等待批准/已通过/被驳回）；
  - 「当前等你做什么」摘要条（如：「G2 行为规划正在等待批准 → 去审批中心」）；
  - 基线徽章（B0~B4 显示为「需求基线/设计基线…」+ 建立时间）。
- 折叠隐藏：事件流（默认折叠为「最近动态」，展开按时间倒序，每条翻译成人话：「架构设计文档已提交审查」而不是 `gate_submission.submitted_for_review`）。
- 不该出现：aggregate_id、sequence、事件类型原文。

### 4.4 任务工作台 /projects/:id/tasks/:runId（重点修复对象）

初稿三栏布局回归，但内容重新规定：

**左栏：对话区（回归初稿）**

- 用户指令气泡（用户原话）；
- Agent 进展**叙述**，不是事件流。每条是一次状态汇报，例如：
  - 「我已读完需求，整理出需求规格草案，已提交审查」
  - 「仿真发现 2 处问题，正在修复（第 1 次尝试）」
  - 「综合完成，资源占用正常」
  - 「码流已生成 ✅」
- 每条叙述配「查看详情」链接 → 跳该任务的运行记录页（二级页）；对话区内不设折叠区。
- 禁止：直接把 audit 类别/阶段/动作原文当对话内容（现在的 `gate/… ok` 形态必须消失）。

**中栏：阶段链**

- 保留现有 15 节点链（它是有效的），但：门节点显示中文（「需求审查」而非 G1）；hover 显示门编号供工程师对照流程文件。

**右栏：产物预览**

- 保留现有内容渲染（markdown/代码），增加：产物标题 + 「候选」标签 + 生成时间；技术信息（哈希、修订 ID）收进页脚小字或折叠。

**状态横幅**

- 等待批准：「需求审查正在等待批准」+ 按钮「去审批」（跳审批中心对应提交）。
- 完成：「全流程完成，码流已生成」+ 去运行记录页取证据。
- 失败：人话原因 + 「查看运行记录」链接。

### 4.5 审批中心 /approvals

- 用户目标：快速判断「这份提交该不该批」。
- 队列行显示：项目名、审查项中文名（需求审查/设计审查…）、提交时间、提交人。
- 详情页：
  - 上部：待审产物文档（markdown 渲染）——这是主体，占 2/3 宽度；
  - 下部操作区：批准意见（可选）、**批准按钮**（里程碑门：「批准并建立需求基线」）、驳回按钮（理由必填）；
  - 折叠区：提交人、检查摘要（快照哈希等技术字段一律去运行记录页）。
- 不该出现：snapshot_id、check_results_hash 等技术字段的裸值。

### 4.6 产物库 /projects/:id/artifacts

- 按「需求/行为/架构/寄存器/RTL/约束」中文分组；版本列表 + 内容查看保留；
- 「候选」标签保留（重要治理语义），哈希收进详情页脚。

### 4.7 运行记录 /projects/:id/runs（新二级页，承接全部 L3 内容）

- 按任务列出工具运行：操作、状态、耗时、jobId、错误码；
- 每个运行展开证据清单（文件名、大小、SHA-256）；
- audit 事件原始流在这里展示；
- 这是唯一允许出现技术语言的页面。

## 5. 术语表（UI 中文文案统一）

| 技术词 | UI 文案 |
|---|---|
| Gate G1~G9 | 需求审查 / 行为审查 / 设计审查 / RTL审查 / …（编号 hover 可见） |
| GateSubmission | 审查提交 |
| Baseline B0~B4 | 需求基线 / 设计基线 / RTL基线 / … |
| ToolRun | 工具运行（仅在「运行记录」页出现） |
| EvidenceManifest | 证据清单 |
| awaiting_approval | 等待批准 |
| fail_closed | 已安全停止 |

## 6. 验收标准（逐条可测）

1. 首屏任意页面默认视图中不出现：jobId、64位哈希、`vivado-batch-1`、audit 原文、英文状态枚举。
2. 工作台对话区每条内容是完整中文句子；任一 audit 原始字符串不直接出现在对话气泡里；技术细节只出现在运行记录页。
2b. 项目列表页/首页有「我的待办」聚合：等待我批准的审查 + 我正在跑的任务。
2c. 项目列表页有「新建项目」按钮，对话框只需项目名称即可创建成功并跳转总览。
3. 阶段链门节点默认显示中文名。
4. 等待批准时，用户从工作台出发 ≤2 次点击到达对应审批详情页。
5. 审批详情页默认视图中文档内容占主视觉区；批准按钮文案包含后果（「并建立需求基线」）。
6. 失败场景：横幅显示人话原因，技术细节需一次点击才可见。
7. 构建零错误；既有 32 项前端测试更新后全绿；新增「L3 词汇不出现在默认渲染」的组件级测试（用禁止词表断言）。

## 7. 非目标

- 不改技术栈、不改 Core API 契约；
- 不做新页面（运行记录页、追踪视图留到 UI-3）；
- 不做移动端适配；
- 不引入组件库（保持自研极简组件）。

## 8. 已确认问题（2026-08-13）

1. 角色：工程师与审批者是同一人 → 已加「我的待办」聚合。
2. 门术语：中文为主（需求审查/设计审查…），G 编号 hover 可见。
3. 技术细节：不设折叠区，统一收进运行记录二级页。
