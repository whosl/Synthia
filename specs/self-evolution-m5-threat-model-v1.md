## 1. Overview

### 1.1 Intended use and current baseline

Self-Evolution 将真实任务中的方法沉淀为不可变 Learned Skill，并通过应用、评价和修订提高后续任务成功率。上位 v1 合同要求 Skill 不携带 capability、不直接调用 Connector，也不能批准、建基线、发布或下载硬件；执行仍必须通过 Core 与既有治理（`specs/self-evolution-v1.md:18-27`，§2）。

M5 的新增安全边界包括：发布隐私域、human supersede、bounded diff、problem-family facts、历史 eval evidence 内容读取、Python/TypeScript 安全执行，以及 typed Tcl 到既有四类 Vivado operation 的受约束 handoff。当前实现基线与候选目标必须分开理解：

- **当前有效行为：** Learned Skill files 是数据；Runtime 只暴露 search/view/apply/close，view DTO 对每个文件固定返回 `executable:false`（`runtime/learned-skill-tools.ts:1-14,61-108`）。
- **当前发布行为：** scanner pass 后创建 `active_unproven`，并立即更新单一 `learned_skill.active_version_id`；task search 直接查询该全局 pointer（`core/src/api/self-evolution-handlers.ts:1168-1206,2207-2275`）。
- **当前扫描边界：** scanner 使用扩展名/shape 与 regex deny rules；trajectory sanitizer 使用确定性模式替换。两者是 early quarantine/审计信号，不是隐私证明或执行隔离（`core/src/services/learned-skill-scan.ts:58-121,142-169,181-283`；`core/src/services/trajectory-sanitize.ts:18-68`）。
- **当前 Vivado 边界：** Core 与 Connector 只接受 `validate_sources`、`simulate`、`synthesize`、`implement` 四类 typed operation；Eval API 前置拒绝 `command`、raw Tcl、hardware、program、download、publication 和 caller-selected classification（`core/src/domain/evolution-eval.ts:3-34,261-288`；`core/src/api/evolution-eval-handlers.ts:52-69,164-172`；`connector/evolution-eval.ts:23-30,431-466,511-583`）。
- **候选而非有效控制：** project/global activation revision chains、generic-event/effect-only commit authority、role-derived effect turn binding/object-args producer、application-version-role attachment、full Q/B binding→snapshot→compilation→IR→handoff→dispatch→typed ToolRun identity、OCI sandbox、Deno、CPython-WASI、sandbox key/host certification chain、`.ltcl` grammar/IR 和 `learned_script_typed` run class 都只存在于 M5 Revision 8 候选合同；尚无当前 production implementation（`specs/self-evolution-m5-development-plan-v1.md:48-550`，§2；`specs/self-evolution-m5-development-plan-v1.md:553-639`，§3；`specs/self-evolution-m5-development-plan-v1.md:1874-2020`，§6–7；`specs/self-evolution-m5-development-plan-v1.md:2021-2611`，§8）。

```mermaid
flowchart LR
  H[Human / Web] -->|Bearer, read/control| C[Core API]
  T[Task Runtime] -->|task-runtime singleton token| C
  E[Evolution Service] -->|distiller / curator / scheduler / eval tokens| C
  C <--> DB[(Core PostgreSQL)]

  X -->|evolution_eval only| V[Vivado worker]

  subgraph Planned_M5_C[Planned M5-C isolated execution zone]
    S[Dedicated Sandbox worker]
    O[Certified OCI child]
    I[Deno or CPython-WASI]
    S --> O --> I
    R1["/skill read-only"]
    R2["/input read-only"]
    R3["/output bounded tmpfs"]
    R1 --> I
    R2 --> I
    I --> R3
  end

  C -. exact sandbox token and manifests .-> S
  R3 -. staged hashes/bytes; no automatic adoption .-> C
  C -. planned typed .ltcl compile/rebind .-> X
  I -. no Connector, token, network or hardware authority .-> V
```

The dashed paths are planned contracts, not implemented protections. The security-critical invariant is that learned content never crosses directly into Connector/Vivado or hardware authority.

## 2. Threat Model, Trust Boundaries, and Assumptions

### 2.1 Protected assets

| Asset | Required property | Current or planned |
|---|---|---|
| Project-derived trajectories, source, logs and evidence | Confidentiality follows current project ACL；global content must not retain project/private material | Current sanitizer/scanner and redacted projections；publication redesign planned |
| Learned Skill versions/files/manifests | Immutable content, exact hashes, provenance, no implicit capability | Current |

### 2.4 Security objectives

1. **Privacy and audience binding:** no project-derived Skill content, diff, evidence, output or fixed-application content becomes visible outside its authorized source project unless the selected publication policy explicitly allows it. Under option A, global promotion is a human declassification decision, not a scanner result; every non-no-op global edge is immutable and ABA-fenced, and NULL clear retains explicit authority.
2. **No implicit execution:** `.py`, `.ts`, ordinary `.tcl` and planned `.ltcl` remain `executable:false` data. Python/TypeScript effect is only through a certified sandbox run; typed Tcl effect is only through Core compile/rebind and the four-operation Connector boundary.
3. **Zero child authority:** untrusted child processes receive no Core/Connector/model/cloud/proxy credential, no environment, no host fd/path, no network/IPC/device/hardware capability and no project/Skill/DB write path.
4. **Exact effect binding without generic-event breakage:** Project Agent null-turn objective/recovery/status/message and other generic events remain valid chronology but carry no effect authority. Every script Run/compilation must bind the exact real event, three-name commit fact and attached application/version/skill/role；supporting work never becomes primary attribution. Revision 8 plans canonical Q as application/project/task/version plus exact binding fact id/hash, selection hash, policy hash and toolchain hash, and B as Q plus exact snapshot id/hash; the identical Q/B must propagate through binding fact→snapshot→compilation→IR→handoff→dispatch→typed ToolRun and then operation/request/input lineage. This objective is specified but remains unsatisfied as an effective control until implemented and evidenced.
5. **Fail-closed lifecycle:** signed attestation key, registration rotation, boot attestation, ledger root/genesis, certification, launch, profile, manifest, hash, current lease or kill-proof uncertainty cannot create/retry an effect; ambiguity becomes `unknown_effect` and quarantines the host.
6. **Bounded resource use:** execution and output must remain inside fixed CPU/memory/pids/fd/file/output/wall limits, with whole-tree/container/cgroup/mount termination evidence.
7. **Evidence and output containment:** sandbox output remains project-only and is never automatically adopted into project, Skill, distillation, formal/eval evidence, baseline, release, publication or hardware selectors. Historical evidence is returned only from the exact frozen Core copy after ACL and hash verification.
8. **Hardware separation:** neither current evolution_eval nor planned learned typed handoff grants formal bitstream, download, program or device authority. Trial `.bit` output is never sufficient evidence of authorization.
9. **Auditable decisions:** publication, quarantine, supersede, generation transitions, run state, certification, handoff and evidence readback preserve immutable hashes, revisions, idempotency identity and audit/outbox lineage.

- **Product decision open:** option A (project activation + human global promotion) is the candidate default; option B retains immediate-global with DLP/review/revoke. ## 4. Severity Calibration (Critical, High, Medium, Low)

Severity is assigned only after validation. Impact, reachability, prerequisites, effective controls and confidence are recorded separately. A missing test or planned control is not automatically a vulnerability.

| Level | M5-specific validated example | Counterexample / downgrade condition |
|---|---|---|
| **Critical** | A remotely reachable learned script escapes isolation, obtains Core/Connector/hardware authority and can program or publish hardware without human governance; or a chain gives broad persistent control over Core/DB across projects. | Merely producing an experimental `.bit` is not Critical: current classification and DB triggers bar it from formal/delivery authority, and current eval API has no hardware program route. Physical/hardware reachability must be proven. |
| **High** | A normal project/task actor can reliably read private source-derived Skill/evidence from another project; a learned child can read secrets or make network/host calls; typed `.ltcl` reaches raw Tcl/arbitrary Vivado command; trial output crosses into formal/download/program authority. | If the path requires pre-existing DB/host administrator control, the attacker already possesses equivalent authority and the product-boundary gain may be lower or outside scope. If the relevant M5 feature is absent/default-off and no current route reaches it, record a planned-control gap or open question rather than a reachable High finding. |
| **Medium** | A project-scoped actor can falsify supersede/family facts, revive revoked work, read another application within the same project contrary to binding, cause bounded but material service exhaustion, or inject trusted-looking sandbox output that still requires later human adoption. | Strong project ACL, exact CAS/idempotency, bounded quotas, no automatic adoption, and rapid host quarantine reduce likelihood/impact. Self-only quality changes with no downstream selector effect may be Low. |
| **Low** | Limited metadata leakage, deterministic error/timing differences with no protected-content disclosure, or UI/resource effects confined to the attacker's own authorized record and bounded session. | Cosmetic differences, documented ordinary behavior, or data the actor is already authorized to read are not security impact. |

### 4.1 Required calibration rules

- **Current non-executable scripts:** a learned `.py`, `.ts` or `.tcl` file containing dangerous-looking text is not a code-execution finding while the only model-facing path returns `executable:false`. It remains adversarial input for M5-C tests.
- **Scanner result is not proof:** scanner pass does not prove privacy or sandbox safety; scanner fail also does not prove exploitability. Severity follows the authoritative audience/execution boundary actually crossed.
- **Trial bitstream is not formal hardware authority:** `.bit` under `experimental/evolution_eval` / `evolution_eval_only` is expected current behavior. A finding requires a validated selector, classification or programming-boundary failure.
- **A/B decision changes expected behavior:** before the product chooses publication semantics, immediate-global visibility is an established current behavior and a privacy-design hypothesis, not automatically an unauthorized-access finding. After a decision, severity follows the promised audience invariant.
- **Planned controls do not reduce current severity unless deployed:** OCI, Deno/WASI, `.ltcl`, generation gates and sandbox certification cannot be counted as effective mitigations until implementation, certification and Gate evidence exist. Conversely, their absence is not currently reachable script execution because no learned-script execution route exists.
- **Confidence is separate:** source-established reachability and control failure can support high confidence without runtime exploitation. Missing deployment facts—network exposure, host ACL, hardware attachment, DB roles—must lower confidence or remain explicit prerequisites, not be silently assumed.
